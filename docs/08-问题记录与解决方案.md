# 问题记录与解决方案

本文记录本轮酒馆手机插件改造中出现过的主要问题、定位原因和最终处理方式。后续遇到同类问题时，优先按这里的排查顺序处理。

## 1. 修改后网页仍显示旧 UI

现象：

- 源码和 `dist` 已经更新，但浏览器里的首页灰字、档案按钮、统计页仍是旧样式。
- 直接刷新页面后仍不生效。

原因：

- 当前工作区构建的是根目录 `dist`。
- 酒馆实际加载的是扩展目录中的 `third-party/tavern-phone-no-helper-test-20260701-20/dist/index.js`。
- 浏览器通过 `fetch(..., { cache: 'no-store' })` 读取实际加载文件后，确认该文件仍是旧 bundle。
- 当前页面加载的 manifest 显示名为 `酒馆手机测试-无依赖`，对应发布包应同步 `release-no-helper`。

解决方案：

- 每次构建后同步发布目录：
  - `dist/index.js` -> `release-no-helper/dist/index.js`
  - `dist/index.css` -> `release-no-helper/dist/index.css`
  - 如还使用 minimal 包，也同步到 `release-minimal/dist`
- 之后再把对应发布目录覆盖到酒馆实际扩展目录，重启或强刷酒馆页面。

注意：

- 仅运行 `pnpm build` 不一定会影响当前网页，除非工作区本身就是酒馆正在加载的扩展目录。
- 判断是否真的加载新文件，不看页面表现，优先在浏览器里 `fetch` 实际扩展 URL 检查 bundle 内容。

## 2. 构建产物和发布包不同步

现象：

- 根目录 `dist` 是新逻辑，`release-no-helper/dist` 还是旧逻辑。
- 发布包里的旧 `index.js.map` 还存在，看起来像构建又生成了 map。

原因：

- `vite.config.ts` 当前输出目录是根目录 `dist`。
- `release-no-helper`、`release-minimal` 是独立发布目录，不会被 Vite 自动更新。
- `sourcemap: false` 只影响新构建，不会自动删除历史残留 map 文件。

解决方案：

- 构建后复制根目录产物到发布目录。
- `manifest.json` 只引用 `dist/index.js` 和 `dist/index.css`，旧 map 不影响运行。

注意：

- 本轮尝试删除旧 map 时文件系统返回 Access denied，因此保留为无引用历史文件。
- 后续可以用发布脚本自动同步并清理发布目录，避免人工漏同步。

## 3. 沙箱内 build 失败

现象：

- `pnpm build` 在普通沙箱中失败：
  - `failed to load config`
  - `Error: spawn EPERM`

原因：

- Vite/esbuild 需要启动子进程，当前 Windows 沙箱环境会拦截部分 spawn。

解决方案：

- 使用已批准的非沙箱方式执行 `pnpm build`。
- `pnpm lint src` 可在普通环境运行，作为快速语法和规则检查。

注意：

- `lint` 通过不代表 bundle 一定能构建。
- 构建通过后仍需确认发布目录是否同步。

## 4. 首页非生成类 App 灰字过多

现象：

- 首页所有 App 都显示灰色说明，视觉噪声重。
- 聊天档案、收藏、提示词、阅读聊天、设置等非生成类 App 的灰字没有必要。

原因：

- 首页 tile 统一渲染 subtitle，没有区分生成类 App 和工具类 App。

解决方案：

- 在 `PhoneOverlay.vue` 中通过 `getHomeAppSubtitle` 限制摘要显示范围。
- 仅生成内容类 App 显示摘要：
  - 总结
  - 日记
  - 番外
  - 论坛
  - 小剧场
  - 书信
- 非生成类 App 返回空字符串，并用 `v-if` 不渲染 `<small>`。

注意：

- 首页摘要用于表现“当前聊天已有创作内容”，不是 App 功能介绍。
- 新增工具类 App 时默认不应显示灰字。

## 5. 统计页 UI 严重错位

现象：

- 统计页出现竖排文字、数字挤压、区域间距混乱。
- 大数字和标题在窄屏中互相压迫。
- “当前聊天内容”“当前聊天楼层统计”等信息层级不清楚。

原因：

- 旧统计页复用的统计卡片布局不适合大量指标。
- 部分卡片没有稳定的 grid 约束，长文字会挤压数字。
- 内容列表、指标和折叠按钮混在一起。

解决方案：

- 重构 `StatsApp.vue` 页面结构：
  - 顶部概览区只放当前作用域和刷新按钮。
  - 创作内容用 App 行列表展示，左侧名称与元信息，右侧字数。
  - 当前聊天内容和楼层统计拆成独立区块。
  - 指标卡统一使用左侧文字、右侧数字的 `pc-metric-card`。
  - 每楼字数分布使用条形列表，避免大面积空白。

注意：

- 统计类页面不要使用大块装饰卡片堆叠。
- 数字指标优先用行式或两列 grid，避免一列里同时塞标题、说明、大数字。

## 6. 档案详情页多余导航按钮

现象：

- 档案详情页顶部出现“跳转 / 首页 / 当前”三个按钮。
- 同样能力已经存在于手机顶栏和首页导航条里，重复且占空间。

原因：

- 早期为了历史聊天跳转新增了 `ArchiveContextBar`，后来首页导航条承担了相同职责。

解决方案：

- 从 `ChatArchiveApp.vue` 的详情页移除 `ArchiveContextBar`。
- 删除对应 import 和跳转函数调用。

注意：

- `ArchiveContextBar.vue` 文件本轮因文件系统 Access denied 未能删除，但已无运行引用。
- 后续如果要恢复上下文操作，应优先复用首页导航条，而不是在详情页再放一组按钮。

## 7. 导航跳转和档案索引混淆

现象：

- 当前聊天导航条显示正常，但档案索引里聊天名可能显示 `__no_chat__` 或旧数据。
- 历史聊天、当前聊天、未选择聊天之间容易混淆。

原因：

- 插件早期数据按当前聊天写入，缺少独立的角色卡/聊天索引视图。
- 旧数据可能没有完整 chat id，只能落到 `__no_chat__`。
- “跳转到档案详情”和“跳转到酒馆聊天”是两种不同动作。

解决方案：

- 新增聊天档案 App：先按角色卡分组，再显示聊天列表，再进入该聊天所有 App 内容。
- 首页导航条显示当前阅览的角色卡与聊天，并提供：
  - 跳转酒馆聊天
  - 回到酒馆当前聊天
- 非当前聊天默认只读，不允许生成。

注意：

- 档案 App 用于查看和区分哪些聊天有数据。
- 跳转按钮必须明确跳转到酒馆聊天，不是跳到档案页。

## 8. 阅读聊天卡在当前聊天

现象：

- 从档案进入历史聊天后，阅读聊天仍显示“当前聊天”内容。
- 用户期望阅读选中的历史聊天，而不是酒馆当前聊天。

原因：

- 阅读聊天早期按酒馆当前聊天取消息，没有使用手机当前阅览作用域。

解决方案：

- 阅读逻辑改为读取 `phone.viewingScope`。
- 如果阅览的是历史聊天，解析对应角色卡和 chat file。
- 历史聊天只读，生成类操作禁用。

注意：

- “酒馆当前聊天”和“手机正在阅览的聊天”是两个概念。
- 所有内容查看类 App 应优先尊重手机阅览作用域。

## 9. 导入导出作用域不清楚

现象：

- “导入到当前聊天”容易误解：当前是酒馆当前，还是手机正在阅览的历史聊天？
- 换聊天导入可能把内容写错作用域。

原因：

- 备份动作没有明确区分当前聊天备份和全部备份。
- 用户跨设备迁移时，也需要知道插件内数据是否跟随酒馆备份。

解决方案：

- 设置页按钮改成明确短文案：
  - 导出全部
  - 导出当前
  - 导入当前
  - 导入全部
  - 清空当前
  - 清空全部
- 当前作用域以手机阅览作用域为准，并在设置页显示当前作用域。
- 完整备份包含插件内数据；自定义壁纸和字体源文件不写入 JSON，只保存路径/配置。

注意：

- 换电脑或手机时，建议先导出完整备份，再在新设备导入。
- 如果自定义壁纸/字体文件不在新设备对应路径，需要重新导入资源文件。

## 10. 字体、首行缩进、每行空行不生效

现象：

- 设置里选择字体后，手机界面或阅读器字体变化不明显。
- 首行缩进、每行空行依赖 AI 输出，AI 没写就没有。

原因：

- 手机主体通过 Teleport 挂到 `body`，不是 `#phone-creative-root` 内部。
- 早期 CSS 使用 `#phone-creative-root ...`，实际匹配不到手机 UI。
- SillyTavern 全局字体规则带 `!important`，普通选择器压不过。
- 阅读正文里每行空行不能依赖 AI 生成格式，应该渲染前规范化文本。

解决方案：

- 全局样式改用 `.pc-phone-root` 作为根选择器。
- 增加高优先级字体规则，覆盖酒馆全局字体。
- 阅读器正文使用 `--pc-reader-font-family`、`--pc-reader-font-size`、`--pc-reader-line-height`。
- `ReaderApp` 渲染前根据设置规范化文本：
  - 开启每行空行时，非空行之间固定插入且只插入一个空行。
  - 开启首行缩进时，去掉原始行首空白，交给 CSS `text-indent` 处理。

注意：

- 字体要看正文区域是否应用，不要只看设置页标签。
- 如果外部页面样式继续使用更高优先级规则，仍需在 `.pc-phone-root` 下补足覆盖。

## 11. 详情页目录文字挤压和按钮风格不一致

现象：

- 日记详情页目录按钮文字挤在一起。
- 底部按钮有时退回浏览器默认按钮样式。

原因：

- 详情页按钮布局没有统一稳定尺寸。
- 有些按钮写在各 App scoped CSS 中，优先级和结构不一致。

解决方案：

- 抽出统一详情底部结构 `DetailFooter`。
- 在 `global.css` 中统一 `.pc-detail-footer`、`.pc-detail-nav`、`.pc-detail-actions` 按钮样式。
- 按钮文字在窄屏中隐藏或截断，优先保留图标和 tooltip。

注意：

- 详情页底部操作应优先使用公共组件。
- 不要在每个 App 内重复写一套底部导航 CSS。

## 12. 生成日记提示词格式不合理

现象：

- 日记提示词里出现“格式参考”字样，模型可能照抄说明。
- 时间要求写具体时分，但日记不一定需要精确时间。
- 输出可能带标签外解释。

原因：

- 提示词把说明和样例混在一起，且给了容易被模型照抄的固定时间。

解决方案：

- 改为要求只输出一个完整日记块。
- 保留固定字段名：标题、时间、内容。
- 时间写日记发生或写作日期，不强行要求具体时分。
- 明确不要输出标签外解释。

注意：

- 生成格式要求应尽量像协议，不要像范文。
- 示例不要包含容易被照抄的具体内容。

## 13. “只生成大纲”功能容易误解（已由后续决策取代）

现象：

- 番外里“只生成大纲”看起来像多余模式。
- 用户不知道它和正常生成章节有什么区别。

原因：

- 模式选择缺少功能解释。

最终处理：

- 后续实际使用确认该模式不再需要，已删除入口、生成分支和预览保存分支。
- 旧数据中的 `outline` 字段暂时保留，避免导入旧备份时丢字段，但不再参与类型提示词或章节生成。

## 14. 阅读聊天规则无法新增且不可折叠

现象：

- 阅读聊天规则固定在界面里，无法扩展。
- 规则区域占空间，正文提取规则不方便维护。

原因：

- 规则配置早期写死在页面卡片中。

解决方案：

- 在规则区域左侧增加面板图标。
- 点击展开规则面板。
- 支持新增规则，便于排除正文里不需要的内容。

注意：

- 解析规则属于配置，不应硬塞在正文卡片中。
- 新增规则时要保留默认规则，避免升级后旧用户直接失效。

## 15. 提示词 App 信息结构混杂

现象：

- App 提示词、类型提示词、快捷短语混在一个页面，信息密度高。

原因：

- 早期按“提示词工具”整体设计，没有按用途分区。

解决方案：

- `PromptsApp` 改为三个标签页：
  - App 提示词
  - 类型提示词
  - 快捷短语

注意：

- 工具类 App 不一定需要首页灰字说明，但内部需要清楚的信息架构。

## 16. 总结 App UI 落后于统一风格

现象：

- 总结 App 仍是旧 UI 风格，与日记、番外等页面不一致。

原因：

- 总结 App 较早实现，未迁移到后续统一组件和风格规范。

解决方案：

- 改造总结首页、书本页、详情页、生成页，使其接近日记/番外的页面结构。
- 优先复用统一按钮、详情底部、生成面板和卡片样式。

注意：

- 旧 App 迁移时先对齐结构，再处理局部视觉。
- 不要通过大量覆盖 CSS 修旧页面，应尽量迁移到公共组件。

## 17. UI 覆盖规则越补越多

现象：

- 为了修某个按钮或卡片，容易不断追加更高优先级覆盖。
- 最终同类按钮在不同 App 里风格仍不一致。

原因：

- 可复用组件没有被优先使用。
- scoped CSS 和全局 CSS 边界不清楚。

解决方案：

- 通用结构放到公共组件或 `global.css`：
  - `DetailFooter`
  - `CatalogModal`
  - `GenerationPanel`
  - `GenerationPreviewPanel`
  - `SourcePanel`
  - `InfoHint`
  - `EmptyState`
- 页面私有 CSS 只写页面布局和业务差异。

注意：

- 不需要新增覆盖规则时，就不要新增覆盖规则。
- 先找公共组件，确认不能复用后再写局部实现。

## 18. 旧文件无法删除

现象：

- 删除 `ArchiveContextBar.vue` 失败。
- 删除发布目录旧 `index.js.map` 失败。
- PowerShell 返回 Access denied。

原因：

- 文件系统权限或占用状态异常。

解决方案：

- 功能层面先移除所有引用，确保不进入运行路径。
- 对 manifest 未引用的历史文件，记录为残留文件，不影响运行。

注意：

- 不要为删除文件使用破坏性 git 命令。
- 后续可在手动关闭占用或修复权限后清理。

## 20. 手机端插件入口正常加载但界面为空

现象：

- 手机端安装后点击打开没有反应，界面不出现。
- 无线调试里能看到：
  - `window.__sillytavernPhoneBuild__` 有值。
  - `#phone-creative-native-launcher` 原生兜底按钮存在。
  - `typeof window.__sillytavernPhoneOpen__ === 'function'`。
  - 但 `.pc-phone-root` 为 `null`，`#phone-creative-root` 为空。
- 控制台报错包括：
  - `Cannot read properties of undefined (reading 'forEach')`
  - `Cannot read properties of undefined (reading 'reader')`
  - `Cannot read properties of undefined (reading 'theme')`
  - `Cannot read properties of undefined (reading 'value')`

原因：

- 入口文件最初静态导入面板逻辑，一旦后续依赖初始化失败，悬浮按钮也可能没有机会显示。
- 设置 schema 的嵌套对象使用了不完整默认值，例如 `customFont.default({ path: '', name: '' })`，内部 `fonts` 没被补成数组。
- 根设置为空或旧结构时，`settings.reader`、`settings.theme`、`customWallpapers.forEach`、`customFont.fonts.forEach` 等渲染依赖会读到 `undefined`。
- Vue 挂载被渲染期异常打断，导致根节点创建了但没有实际 UI。

解决方案：

- 在 `src/index.ts` 顶层先创建原生兜底按钮，再动态导入面板 chunk。
- `vite.config.ts` 设置 `base: './'`，保证拆包后的 `panel.*.chunk.js` 和 `panel.css` 通过相对路径加载。
- 给 `Settings` schema 的嵌套默认值补完整结构：
  - `customFont.fonts: []`
  - `wallpaper.customWallpapers: []`
  - `reader`、`generation`、`textProvider` 全字段默认值
  - `layout.appOrder: []`
- 在设置归一化里对 `customWallpapers` 和 `customFont.fonts` 再做数组兜底。
- 更新 build marker，方便无线调试确认手机端加载的是新包。

注意：

- 遇到“按钮存在但手机不打开”时，先在无线调试里检查：
  - `window.__sillytavernPhoneBuild__`
  - `document.querySelector('#phone-creative-native-launcher')`
  - `document.querySelector('#phone-creative-root')`
  - `document.querySelector('.pc-phone-root')`
  - `typeof window.__sillytavernPhoneOpen__`
- 如果 `.pc-phone-root` 仍为 `null`，优先看控制台第一条 Vue 渲染错误，不要继续只调悬浮球。
- schema 默认值要给完整嵌套结构；不要依赖空对象默认值自动补内部字段。
