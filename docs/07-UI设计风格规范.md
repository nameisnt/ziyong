# UI 设计风格规范

本文档记录酒馆手机的基础视觉规范。卡片使用、页面密度、标题、说明文字、字体归属和迁移顺序已由
`16-全局扁平UI设计与迁移方案.md` 更新；两者冲突时以文档 16 为准。

## 设计目标

酒馆手机不是营销页，也不是传统表单后台。它应当像一个轻量、现代、可反复使用的手机工具：

- 第一屏直接可用，不放说明型欢迎页。
- 信息密度适中，优先服务阅读、生成、管理和跳转。
- 控件风格一致，避免浏览器原生按钮、输入框和旧式边框混入。
- 手机窄屏优先，桌面浮窗只是更宽一点的同一套体验。
- 所有 App 使用同一套页面骨架、按钮、列表、底部操作区和弹窗语言。

## 视

整体基调为 iOS 风格的浅浮层界面：

- 背景：由手机壳统一提供，不在 App 内重复做大面积渐变。
- 面板：页面小节默认无框，只有独立内容对象、状态和预览使用 surface 边界。
- 圆角：普通列表和表单分组不依赖圆角表达层级；独立内容卡默认不超过 `8px`，按钮按控件规范使用固定圆角。
- 阴影：只用于弹窗、手机壳等浮层；App 内列表卡片不做重阴影。
- 色彩：默认中性色 + 少量蓝色强调。不要让某个 App 变成单独的高饱和主题。

推荐变量：

- `var(--pc-bg)`
- `var(--pc-surface)`
- `var(--pc-surface-strong)`
- `var(--pc-border)`
- `var(--pc-text)`
- `var(--pc-muted)`

## 页面结构

每个 App 根页面统一使用：

```vue
<section class="pc-xxx-app">
  <section class="pc-xxx-page">
    ...
  </section>
</section>
```

页面容器要求：

- 使用 `display: flex; flex-direction: column; gap: 12px-14px;`
- 不在页面顶部额外做大标题横幅，标题由手机顶栏承担。
- 业务内需要上下文时，用紧凑上下文条，不写大段说明。
- 列表项优先使用紧凑列表行；编辑表单优先使用无框小节；空状态和错误状态使用各自统一组件。

## 固定面板高度

游戏、画板、播放器、可视化工作流等需要“整屏工具感”的 App，不应依赖纯 CSS 比例把所有容器一起拉伸。推荐使用“固定区 + 计算剩余区”：

- 从 `settings.interfaceSize.phoneHeight` 读取手机设置高度。
- 扣除全局手机顶栏高度和 `.pc-screen` 上下 padding，得到 App 可用高度。
- 顶部状态栏、进度条、底部操作栏、底部标签栏等结构固定为明确 px 值。
- 容器外部间距优先固定为 `0` 或很小值；内部卡片自己保留 padding。
- 用 `remaining = available - fixedTotal` 计算剩余高度。
- 将剩余高度按业务比例拆成计算后的固定 px，例如事件区 70%、日志区 30%。
- 把结果写入 CSS 变量，如 `--pc-app-event-height`、`--pc-app-log-height`，再用于 `grid-template-rows`。
- 父级 App 容器在该模式下必须 `height: 100%; min-height: 0; overflow: hidden;`，滚动只允许发生在内容区内部。

不要只写 `7fr / 3fr` 或 `minmax(0, 1fr)` 来表达这类主界面高度；这会被外层 padding、父容器 `min-height`
或手机高度设置放大，导致 `.pc-screen` 出现整页滚动条。

## 按钮规范

按钮不能出现浏览器原生边框样式。所有按钮必须显式设置：

- `appearance: none`
- `border: 0`
- `background`
- `border-radius`
- `height` 或 `min-height`
- `font: inherit`

按钮类型：

- 主按钮：用于提交、生成、保存，蓝色填充。
- 软按钮：用于取消、返回、普通操作，surface 填充。
- 图标按钮：用于刷新、编辑、删除、跳转等短操作，优先 lucide/fontawesome 图标。
- 危险按钮：只变文字或图标色为红色，不使用大面积红底。

文字按钮最多四个字。能用图标表达的操作优先用图标，必要时配 `title`。

三按钮操作条应固定三等分一行：

```css
.pc-action-row.three {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 8px;
}
```

## 卡片与列表

列表项统一为可点击整行：

- 外层 `button` 或 `article + button`
- 左侧主信息，右侧数字、状态或箭头
- 标题单行省略
- 副信息使用 `var(--pc-muted)`

统计卡统一为左字右数：

```text
创作内容                         3
```

当数字为 0 时，不显示额外灰色解释。空状态应单独使用空状态卡，而不是塞在统计卡内。

## 生成页

所有可生成内容的 App 优先使用 `GenerationPanel`：

- 来源楼层选择
- 引用内容
- 追加要求
- 酒馆最终提示词捕获
- 错误展示
- 取消、停止、生成按钮
- 原始输出

不要在每个 App 里重复实现生成表单。需要额外业务字段时使用插槽：

- `before-fields`
- `after-references`
- `after-requirement`

生成预览统一使用 `GenerationPreviewPanel`。需要展示最终 HTML 或特殊内容时，再使用插槽扩展。

## 详情页

详情页由三块组成：

- 内容卡：标题、元信息、正文。
- 底部导航：上一章、目录、置顶、置底、下一章。
- 操作条：收藏、编辑、删除、续写、回信等业务按钮。

正文使用 `pc-rendered-markdown`，字体大小和行高跟随阅读器设置。

目录必须使用 `CatalogModal`，列表区域必须可以滚动。

## 弹窗

弹窗统一使用：

- 半透明 mask
- 居中卡片
- 头部固定
- 内容区 `overflow-y: auto`
- 移动端支持 `-webkit-overflow-scrolling: touch`

弹窗不能被内容撑破，也不能让内部列表被外层裁掉。

## 首页与档案导航

手机首页顶部上下文条只承担确认和跳转：

- 左侧显示当前正在阅览的角色卡与聊天。
- 右侧提供跳转酒馆聊天、回到当前聊天等图标按钮。
- 不在这里打开说明页。

聊天档案内的上下文操作条只保留按钮，不显示长说明文字：

- `跳转`
- `首页`
- `当前`

三个按钮固定一行，风格一致。

## 旧 UI 迁移规则

迁移旧页面时按下面顺序处理：

1. 先替换浏览器原生按钮、输入框和 select。
2. 再统一页面卡片、列表项、空状态和错误状态。
3. 再接入 `GenerationPanel` 和 `GenerationPreviewPanel`。
4. 最后清理重复 scoped CSS，把可复用结构抽到组件。

禁止为了快速修视觉问题追加大量覆盖规则。能在组件内统一的，就在组件内统一。

## 总结 App 当前问题

`SummaryApp` 是明显的旧 UI 遗留页，后续应优先改造。

当前问题：

- 首页复用了 `BookShelf` 的 `variant="diary"`，语义和视觉都不准确。
- 页面内仍有大量早期局部样式，和后续 App 的按钮、列表、详情页不完全一致。
- 总结集管理区和书架入口重复，信息层级混乱。
- 详情页底部按钮已经部分统一，但列表页和编辑页仍偏旧。
- 失败草稿、生成入口、总结条目列表缺少一致的 App 信息结构。

建议目标：

- 总结首页改为“总结集列表 + 顶部生成入口”，不再用日记书架变体。
- 总结集列表使用统一行卡：左侧标题/条数，右侧进入箭头；编辑、删除放详情或滑出操作区。
- 总结集详情页使用统一 hero + 条目列表，生成按钮用图标软按钮或主按钮。
- 编辑页、失败草稿页复用统一 `pc-editor-card` 和表单动作区。
- 详情页保留当前底部导航结构，但按钮样式跟全局详情页完全一致。

## 新 App 检查清单

上线前检查：

- 没有原生边框按钮。
- 没有页面级大段说明文字。
- 所有按钮文字不超过四个字，长说明放 `title`。
- 列表项标题不会溢出。
- 弹窗可滚动。
- 手机窄屏下按钮不挤压变形。
- 生成页使用 `GenerationPanel`。
- 预览页使用 `GenerationPreviewPanel`。
- 详情页使用 `CatalogModal`。
- 统计卡为左字右数，0 不显示灰色补充。
