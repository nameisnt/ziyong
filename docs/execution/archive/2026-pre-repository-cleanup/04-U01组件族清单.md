## 一、权威基线与结束条件

- 机器权威来源：`scripts/baselines/ui-contracts.json` 中 `ruleId=icon-button-aria-label` 的精确签名。
- R02 起点：157 个签名、159 个实际命中，分布在下表 44 个组件族。
- U01 结束条件：该规则的签名与实际命中均降为 0，且 `protected-control-geometry` 67 处、`protected-control-theme-color` 3 处不在 U01 中变化。
- 每批只处理一个组件族，只增加与既有准确 `title` 同义的 `aria-label`；title 不准确或动作语义不明确时停止并另立缺陷，不自动改文案或事件。

## 二、确定性选择规则

1. U01C 固定为恢复管理组件族，因为已有九个隔离视觉 fixture，可在不触碰真实备份的前提下验证。
2. U01C 后按“剩余实际命中数降序、组件族 ID 升序”选择下一族；相同 App 或同一共享功能目录的多个文件视为一个组件族。
3. 激活下一族时才建立新的 D 编号、工作树归属和批次契约；登记完成前只允许只读检查。
4. 每批完成后从机器基线删除且只能删除本族的精确签名，更新本表实际数量和状态；不能用另一处新增命中抵消旧命中。
5. 当前族缺少隔离视觉场景时，先登记只覆盖该族的测试场景；如果只能操作真实数据，则停止并请求授权。

## 四、U01 之后的自动发现门

U01 清零不直接授权修改 U02 或后续业务。每个后续阶段先建立 `DISC-<阶段>` 只读发现批次，完成复现、D 编号、共同根因、消费者范围和隔离验证设计；没有用户语义选择、C 级操作或不同根因扩张时，才登记并自动进入该阶段第一个实施批次。

Git commit/push、真实酒馆 T3、真实聊天/备份/设置、真实 API、schema、迁移和兼容回退始终不因本队列获得授权。
