## 确认缺陷

### AUDIT-01 / P2 / 通知输入框与弹窗焦点冲突

- 位置：`src/composables/usePhoneModalLifecycle.ts:108`，`src/components/PhoneOverlay.vue:64`。
- 当前本地构建复现：打开预设条目分组管理，点击新建分组，在通知的名称输入框按真实 Tab 键。
- 结果：焦点从 `.pc-phone-notice-input` 回到下面管理弹窗的“新建条目分组”，未进入通知的创建/取消按钮。两次复现一致。
- 根因：通知位于 dialog 外，未进入 modalStack；父弹窗把通知焦点判定为越界并抢回。
- 修复范围：共享交互通知和弹窗焦点层级，不要逐页取消焦点约束。
- 推荐：让交互式 prompt/confirm 通知成为当前顶层焦点作用域；普通非交互通知不改变焦点。回归 Tab、Shift+Tab、Enter、Escape、关闭恢复，以及其他弹窗调用通知的路径。

### AUDIT-02 / P2 / 状态栏异步失效后一直加载

- 位置：`src/apps/status-display/StatusDisplayApp.vue:198` 的 `refreshStatus`。
- 当前本地构建复现：延迟 MVU 初始化，触发方案加载，在完成前把当前 scope 的已启用方案设为空，再完成初始化。
- 结果：`enabledCount=0`，但 `.pc-status-loading` 仍然存在。两次复现一致。
- 根因：新刷新先增加 revision，未选方案分支提前返回而不清除 loading；旧请求 finally 因 revision 不匹配也不能清除它。
- 修复范围：状态栏刷新起始和提前返回路径的加载状态管理。回归无方案、切换到历史聊天、快速切换方案、加载失败、停用再进入，不移除已有过期结果保护。
- 触发依赖异步加载中的配置变化；通常已加载完成的阅读不受此问题影响。

### AUDIT-03 / P2 / 完整类型检查范围过宽

- 位置：`tsconfig.json:47` 附近 include 中的 `../../../../**/*.js`。
- 当前工作区位于 E 盘根目录下一层，该配置会把 JS 枚举范围扩到工作区外；历史完整检查曾发生内存不足。本轮未再次启动这种全盘范围的类型检查。
- 推荐：限制到项目源码和明确的宿主类型声明。需要另行处理宿主模块类型，不能仅删除路径后忽略报错。
- 影响开发验证，不等同于插件运行时全盘扫描。
