# 代码与 UI 分批整理复用方案

## 目标

在不一次性大改全部 App 的前提下，分批整理现有代码和 UI：

- 先收敛已经稳定的重复模式，再处理特殊 App。
- 优先复用全局样式和通用组件，减少 App 内局部重复 CSS。
- 每一批都要能独立验证，不依赖后续批次才能稳定运行。
- 文档、组件、样式和检查脚本保持同步，避免整理后再次分叉。

## 当前资产

已有可复用资产：

- 全局控件样式：`.pc-primary-btn`、`.pc-soft-btn`、`.pc-icon-btn`、`.pc-segment-btn`。
- 全局输入样式：`.pc-field`、`.pc-select`、`.pc-area`、`.pc-field-group`、`.pc-field-label`。
- 全局容器样式：`.pc-section-card`、`.pc-editor-card`、`.pc-form-actions`。
- 通用组件：`EmptyState`、`GenerationPanel`、`GenerationPreviewPanel`、`RawOutputEditor`、`ReferencePicker`、`BaguScanPanel`、`FailedDraftList`、`DetailFooter`、`InfoHint`、`CapsuleTag`、`SearchableCombobox`。
- 通用工具：`formatReaderContent`、`useDetailScroll`、`formatGenerationReferences`、`generationService`、各领域 generation adapter。
- 检查脚本：`scripts/check-ui-reuse.ps1`、`scripts/ui-visual-check.mjs`。

## 扫描结论

体量最大的 Vue 文件集中在：

- `ExtrasApp.vue`、`DiaryApp.vue`、`ForumApp.vue`、`TheaterApp.vue`、`LettersApp.vue`、`SummaryApp.vue`：内容创作类 App，页面结构高度相似，是第一批整理重点。
- `SettingsApp.vue`、`PhoneOverlay.vue`、`ReaderApp.vue`：手机框架与设置/阅读基础能力，影响面大，应放在内容类 App 稳定后处理。
- `RelationshipApp.vue`、`ProfilesApp.vue`、`DigestApp.vue`、`MediaGenerateApp.vue`：已接入部分生成通用组件，但仍有局部页面模式可继续收敛。

重复模式主要集中在：

- 书架/列表/记录页：标题区、排序、搜索、空状态、失败草稿入口。
- 详情页：正文卡片、底部导航、收藏/编辑/删除、八股检测。
- 编辑页：标题/正文/元数据字段、底部取消保存。
- 生成页：来源楼层、引用内容、提示词预览、运行态、停止按钮。
- 预览页：预览/八股/原始输出/保存。
- 失败草稿页：失败提示、原始输出编辑、重新解析、删除草稿。
- 局部 CSS：多个 App 仍在 scoped style 中重复定义 `.pc-editor-card`、`.pc-form-actions`、`.pc-area`、`.pc-soft-btn.danger` 等基础形态。

## 分批方案

### 第 1 批：内容创作 App 页面骨架

范围：

- 日记、番外、总结、书信、论坛、小剧场、摘抄、资料。

目标：

- 抽出或明确复用一套内容 App 页面骨架。
- 降低每个 App 对局部 `.pc-editor-card`、`.pc-form-actions`、`.pc-area` 的重复定义。
- 保持现有业务逻辑不变，只整理结构和样式。

建议抽象：

- `ContentListHeader`：标题、数量、搜索、排序、生成入口。
- `ContentDetailShell`：正文区、标题区、底部 `DetailFooter`、可选八股入口。
- `ContentEditorShell`：编辑卡片、字段区、底部操作区。
- `FailedDraftRepairShell`：失败提示、`RawOutputEditor`、删除/重新解析按钮。

优先顺序：

1. 日记、总结、书信：结构最接近，适合先统一。
2. 番外：多了章节/大纲/总结模式，复用后再保留分支。
3. 论坛：帖子和回复分支特殊，放在内容类最后处理。
4. 小剧场：标签、渲染模式、Frontend 预览特殊，单独收尾。

验收：

- 每个 App 的详情页仍能阅读、翻页、置顶/置底、收藏、编辑、删除。
- 生成、预览、失败草稿可用。
- `check-ui-reuse.ps1` 不出现新增基础控件重复样式。
- `pnpm lint`、`pnpm build` 通过。

### 第 2 批：生成与失败草稿逻辑抽象

范围：

- 所有接入 `GenerationPanel` / `GenerationPreviewPanel` / `FailedDraftList` 的 App。

目标：

- 把重复的 `preview` 状态、`failedDraftRawOutput`、`reparsePreviewRaw`、`reparseFailedDraft` 流程收敛。
- App 只保留领域解析和保存逻辑。

建议抽象：

- `useGenerationPreviewFlow`：管理 raw、warnings、短内容自动重解析、保存前检查。
- `useFailedDraftRepairFlow`：管理 active draft、raw output、更新失败草稿、解析成功后进入预览。
- `createSimpleXmlRepairHandlers`：给日记/总结/书信/摘抄这类 `title + content` XML 使用。

风险：

- 番外、论坛、关系网、媒体生成解析分支不同，不能强行套简单 XML。
- 失败草稿里保存的 context 各 App 不一致，抽象时要保留 adapter 层。

验收：

- 正常预览修改原始输出后，保存前会重新解析。
- 预览正文过短时会自动重新解析，失败时显示弹窗。
- 失败草稿修复成功后进入正常预览，保存后删除草稿。

### 第 3 批：阅读、正则、八股、资料流

范围：

- 阅读聊天、正则显示、八股检测、摘抄、收藏。

目标：

- 明确“显示正文”和“原楼层内容”的边界。
- 将正文清理、正文替换、写回楼层整理成可复用能力。

建议抽象：

- `useReaderWriteback`：封装当前聊天校验、正文回填、`setChatMessagesSafe`、`saveChat`、刷新。
- `ReaderBodyEditor`：手机内编辑正文并写回酒馆楼层。
- `ReaderRuleSelector`：标题规则、正文规则、正文清理多选。

风险：

- 正文规则如果无法唯一定位原文，必须阻止写回。
- 历史聊天必须保持只读。

验收：

- 阅读详情可在手机内编辑正文并写回当前酒馆楼层。
- 八股检测写回仍能使用相同写回链。
- 历史聊天编辑和写回均被禁用。

### 第 4 批：设置与手机框架

范围：

- 设置页、手机顶部 header、底部 dock、悬浮球、手机尺寸适配。

目标：

- 将设置页继续拆成稳定的区域组件。
- 把“固定 header + 固定 tabs + 内容区滚动”的模式沉淀为通用布局。
- 保持手机尺寸设置和自动适配逻辑一致。

建议抽象：

- `PhoneFixedPanelLayout`：固定顶部/标签/底部，中间滚动。
- `SettingsSectionCard`：设置区标题、说明、恢复默认、操作按钮。
- `SettingsSliderField`：标题、当前值、滑块、数值输入。
- `SettingsDangerZone`：危险操作统一二次确认。

风险：

- 设置页长，误触风险高；拆分时不要扩大按钮尺寸。
- 手机外边距和宽高适配会影响所有 App，必须截图验证。

验收：

- 设置标签固定，内容区独立滚动。
- 适配当前窗口计算正确，保留最小/最大限制。
- 手机 header 改动不导致 App 内容错位。

### 第 5 批：媒体与 ComfyUI

范围：

- ComfyUI、媒体生成、相册、音乐、视频。

目标：

- 区分生成、存储、查看三种 App 职责。
- 将媒体查看器、播放器、下载/删除/编辑动作收敛。
- Comfy 工作流参数视图继续保持“节点 + 参数 + 占位符”清晰分层。

建议抽象：

- `MediaLibraryShell`：相册/音乐/视频共用列表和空状态。
- `MediaViewerActions`：下载、删除、编辑、返回。
- `ComfyWorkflowParameterList`：固定/用户参数/AI 生成/占位符说明。
- `ComfyWorkflowSection`：基础运行参数和工作流参数可折叠。

风险：

- `dist` 不能做拆包；酒馆不接受拆包产物。
- Comfy 工作流参数可能是动态 JSON，必须避免字符串硬解析。

验收：

- 媒体生成只负责生成，媒体查看分别在相册/音乐/视频。
- 音频播放器支持进度拖动。
- Comfy 参数切换和占位符替换不影响用户固定参数。

### 第 6 批：小游戏

范围：

- 2048、五子棋、扫雷、贪吃蛇、数独、数织、黑白棋、数字华容道、猜数字、纸牌接龙。

目标：

- 分离小游戏容器、状态持久化、底部操作栏、弹窗。

建议抽象：

- `MiniGameShell`：统一标题、内容区、操作区。
- `MiniGameActionBar`：图标按钮、重置、暂停/继续。
- `MiniGameModal`：结果、确认、说明。
- `miniGameStorage`：继续作为轻量游戏持久化入口。

风险：

- 游戏画面要优先保证不滚动、不错位、按钮可点。

验收：

- 所有小游戏不显示多余标题说明和列表按钮。
- 面板在默认 700 高度下可用。

## 代码整理原则

- 每批只处理一类重复，避免“顺手重构”扩大风险。
- 先抽 UI 容器，再抽业务流程；业务抽象必须等相似流程稳定后再做。
- 抽象组件的 props 要少，复杂差异交给 slot。
- App 内 scoped style 只保留布局、业务状态、特殊视觉；基础控件交给 `global.css`。
- 每次改 UI 后运行 `scripts/check-ui-reuse.ps1`。
- 每批结束至少运行 `pnpm lint` 和 `pnpm build`。

## 建议执行顺序

1. 先统一日记/总结/书信详情页和编辑页。
2. 再统一日记/总结/书信失败草稿修复流程。
3. 推广到摘抄/资料/关系网。
4. 处理番外/论坛/小剧场特殊分支。
5. 整理阅读/正则/八股写回链。
6. 整理设置页和手机框架布局。
7. 整理媒体与 ComfyUI。
8. 单独整理小游戏。
