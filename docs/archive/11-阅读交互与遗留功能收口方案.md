## 一、本轮已经确认的产品决定

1. 日记和总结点击“添加”后使用居中选择弹窗，不再先跳转到“选择创建方式”页面；点击遮罩空白处关闭。
2. 阅读详情点击正文中部后，只显示“上一章、置顶、目录、置底、下一章”五个导航动作。
3. 编辑、橡皮擦、收藏、八股检测、删除和版本切换等动作进入可拖动的半透明阅读工具方块。
4. 切换版本时保持用户当前阅读高度，不再跳到版本栏所在的正文上方或下方。
5. 设置中的“版本切换位置：正文上方/正文下方”失去意义，应删除；旧设置只做兼容读取，不继续影响界面。
6. 阅读聊天的橡皮擦不能再要求选中文字在正文中唯一出现；重复出现时必须允许用户选择具体位置。
7. 除酒馆备份阅读保持只读、阅读聊天写回真实楼层外，日记、总结、番外、书信、小剧场等内容默认直接覆盖当前条目或当前版本，不因修改一句话自动创建新版本。
8. 番外摘要解析失败只显示提示并保留正文；不创建空摘要，也不让章节生成或保存失败，用户仍可稍后单独生成总结。
9. 上一轮聊天档案中明确列出的剩余工作需要继续完成，不能只停留在分析记录。
10. 图片中列出的未完成和部分完成项目全部纳入本文，不再遗漏。
11. 设置快照不再提供正文阅读入口；列表直接提供恢复和单份删除，避免下载、解析和格式化大型 `settings.json` 导致卡顿。
12. 聊天备份查重结果提供“全选可删除项”和“全部取消”；扫描完成后默认选中除保护项外的全部安全候选。
13. 聊天档案增加“当前聊天”标签页，直接提供立即备份、阅读、导出、导入和空聊天插入，减少多层目录操作。
14. 预设管理增加预设级改名和删除，并同步迁移或清理插件内按预设名称保存的绑定。
15. 世界书槽位主列表只显示灯色、条目名和启停状态；世界书联动增加灯色，并提供完整引用迁移的世界书改名。

## 二、实施前代码验真（历史记录）

本节保留开始修改前的审计结论，便于追溯本轮为何改造；其中“当前”“仍然”等表述指实施前状态，完成结果以“零、实施记录”和文末验证记录为准。

### 2.1 版本切换仍会主动跳转高度

当前 `src/util/detailScroll.ts` 的 `scrollToVersionPosition()`
会根据设置跳到顶部或底部；番外、书信、小剧场和论坛在切换版本后仍调用该行为。`ReaderDetailShell.vue`
也仍把版本栏插入正文上方或下方，`SettingsInterfacePanel.vue` 仍提供位置开关。

因此本项尚未完成，不能只把版本按钮搬进菜单，还必须删除切换后的自动置顶/置底路径。

### 2.2 橡皮擦仍受唯一匹配限制

当前 `ReaderApp.vue` 使用
`body.indexOf(selectedText)`，如果第二次找到同样文字就直接报错，要求改用“编辑正文”。写回原楼层时也优先依赖正文在原始楼层中唯一出现。

因此需要同时解决两个定位问题：

- 选中文字在正文中的具体出现位置。
- 正文提取结果在原始楼层中的精确捕获范围。

### 2.3 多个生成 App 仍把楼层数重置为 20

番外、论坛、总结、日记、书信和小剧场仍在打开或重置草稿时直接把 `fromStartEnd`、`recentCount` 等值写为
`20`。这会覆盖用户上次输入。

### 2.4 手机桌面仍是固定 Dock 模型

`PhoneOverlay.vue` 仍通过 App 注册信息中的 `defaultDock`
决定 Dock 归属。拖动只会调整主界面 App 顺序，不能拖入或拖出 Dock。Dock 只有列数设置，没有独立的容量、超量和置换规则，也没有文件夹数据模型。

### 2.5 目前只有首页左右换页手势

现有手势只在首页网格切换分页，没有详情页从左右侧区域向中间滑动返回的实现。

### 2.6 阅读器设置仍然分散

字号、行高、缩进等位于“界面设置”，阅读字体和正文颜色仍位于主题 App，没有真正独立的阅读器设置页面，也没有阅读背景配置。

### 2.7 备份教程和视觉回归仍不完整

教程仍主要描述旧的聊天备份入口和完全哈希查重，没有完整解释“聊天备份/设置快照”双入口、设置恢复、设置查重、续长查重、候选阅读与返回扫描结果。

视觉场景已覆盖旧的书架、角色分组、清理、查重、阅读、确认和结果页，但尚未完整覆盖设置快照列表、单份删除、快照查重、快照恢复、续长候选双向阅读以及新版双入口首页。设置快照正文阅读不再属于待补场景。

### 2.8 设置快照删除只能从查重结果进入

底层已经能够通过酒馆 Data
Maid 清理报告取得一次性令牌和文件哈希，并精确删除设置快照；但当前列表行仍会读取完整快照进入阅读页，单份快照没有直接删除入口。大型快照的下载、JSON 解析和格式化会造成明显卡顿。

### 2.9 聊天查重没有统一的保护集合与全选

完全一致候选扫描后默认全选旧副本，严格续长包含候选默认不选；两类结果各自维护选择和删除按钮，没有“全选可删除项/全部取消”。同一文件也缺少跨两类分组统一判定的保护身份。

### 2.10 聊天档案缺少当前聊天快捷入口

聊天档案首页目前只有“已用过”和“未使用”，即使只想立即备份当前聊天，也需要先进入角色卡、聊天列表和聊天详情。

### 2.11 预设管理只管理预设内部条目

当前预设管理可以查看、切换、编辑、复制、删除和排序预设条目，但不能修改或删除整个预设。酒馆原生预设管理器已经提供
`renamePreset()` 和 `deletePreset()`，本插件尚未封装预设级生命周期以及名称引用迁移。

### 2.12 世界书列表信息与名称生命周期仍未收口

世界书槽位主列表仍显示正文、插入位置、顺序和同步 ID；世界书联动条目有启停状态和插入位置，但没有直接显示蓝灯、绿灯或向量策略。世界书联动也没有世界书改名入口，而插件联动基线和各聊天配置都以世界书名称为键，不能只改酒馆文件名。

## 三、通用阅读详情改造

### 3.1 结构

统一改造 `ReaderDetailShell.vue`，所有复用该壳的阅读页面自动获得相同行为：

- 正文中部点击：只切换五键导航条。
- 阅读工具方块：独立悬浮，不占据正文布局高度。
- 工具菜单：承载版本、编辑、橡皮擦、收藏、八股检测、分支、重写、删除及 App 特有动作。
- 备份阅读：不提供编辑和橡皮擦。

五键导航继续复用 `DetailFooter.vue`。工具菜单优先复用现有 `ActionMenu.vue`
的动作展示和外部点击关闭逻辑；拖动部分提取现有 `FloatingBall.vue`
的指针捕获、拖动阈值、边界限制和位置持久化逻辑，不在单个 App 内重新实现。

### 3.2 阅读工具方块

1. 默认位于阅读区域右侧中部，并与左右屏幕边缘保持安全距离。
2. 闲置时半透明，触摸、聚焦或菜单展开时恢复不透明。
3. 移动超过 6px 才认定为拖动，拖动后抑制本次点击。
4. 位置限制在阅读壳内部，不能覆盖顶栏，也不能拖到正文区域之外。
5. 位置作为统一阅读器设置保存，不按 App 重复保存。
6. 手机尺寸或方向变化后重新夹取合法位置。
7. 菜单根据剩余空间向上或向下展开，点击菜单外部关闭。
8. 工具拖动时阻止事件泄漏到酒馆界面；默认位置避开左右侧返回手势区。

### 3.3 版本切换保持高度

版本切换采用“固定绝对滚动高度”，不采用跳到顶部、底部或按百分比换算：

1. 切换前记录当前阅读滚动容器和 `scrollTop`。
2. 更新当前版本。
3. `nextTick` 后恢复原 `scrollTop`。
4. 下一帧再次校准一次，处理 Markdown 渲染导致的同步布局变化。
5. 新版本内容较短时，只允许夹取到新的最大滚动高度。
6. 版本菜单保持在原悬浮位置，可以连续切换多个版本。

删除以下旧语义：

- `versionNavigatorPosition` 的界面设置。
- 正文上方/下方版本栏插槽。
- 切换版本后调用 `scrollToVersionPosition()` 的路径。
- 教程中“版本栏放在上方或下方”的说明。

旧备份或旧设置中存在 `versionNavigatorPosition` 时允许解析，但迁移后丢弃该字段，不因为旧值改变新界面。

### 3.4 正文高度

工具动作移出底部栏后，阅读详情只为五键导航保留底部安全空间。同步缩小当前为两行工具预留的底部内边距，使正文占用更多高度。

## 四、橡皮擦与整句编辑

### 4.1 重复文字定位

不能再把“是否唯一匹配”当成是否允许编辑的条件。新的流程为：

1. 读取用户在当前正文中的选中文字。
2. 在保存前的正文 `body` 中找出全部出现位置。
3. 只有一个位置时直接进入整句编辑。
4. 有多个位置时先显示候选列表，每项展示段落、句子、出现序号和高亮文字，由用户选择具体位置。
5. 即使同一句中重复出现多次，也按偏移量分别列出，不能合并。
6. 选择后保存正文偏移量；确认写回前重新校验该偏移位置仍是原文字，内容变化时中止写入。

如果显示正则生成了正文原文中不存在的文字，应明确提示“这是显示替换结果，无法安全写回原文”，不能猜测。

### 4.2 整句编辑弹窗

弹窗显示：

- 只读的选中文字。
- 带上下文的原句预览。
- 可编辑的整句文本框。

文本框打开后自动选中对应片段：用户按退格即可删除，直接输入即可替换。选区跨越多句话时，编辑范围扩展为从起始句到结束句；句界以中文和英文终止标点及换行为准。

点击遮罩空白处关闭且不保存。确认后只替换选定偏移量对应的句段。

### 4.3 精确写回正文规则

解析阅读正文时应同时保留正文捕获范围：

```ts
type ReaderBodySourceRange = {
  start: number;
  end: number;
  ruleId: string;
};
```

写回时直接使用该范围替换原始楼层，不能再次依赖 `rawText.indexOf(currentBody)`
的唯一性。确认时重新用同一规则解析原始楼层，验证捕获范围和正文没有变化，再调用安全楼层写入和 `saveChat()`。

### 4.4 不同阅读来源的保存策略

| 阅读来源               | 保存行为                                 |
| ---------------------- | ---------------------------------------- |
| 阅读聊天               | 精确写回当前酒馆聊天楼层，只允许当前聊天 |
| 酒馆聊天备份、楼层备份 | 只读，不显示橡皮擦                       |
| 日记、总结、剧情摘要   | 直接覆盖当前条目正文                     |
| 番外、书信、小剧场     | 直接覆盖当前正在查看的版本，不新增版本   |
| 自定义 App             | 只有注册了可写处理器才显示橡皮擦         |

所有覆盖操作更新对应条目的修改时间，但不改变版本数量。

## 五、日记、总结、书信与番外

### 5.1 日记和总结创建弹窗

- 日记：单篇生成、批量生成。
- 总结：提取总结、新建总结、批量总结。
- 弹窗选择本身不进入路由栈；选中具体动作后才进入实际页面。
- 顶栏返回在弹窗打开时优先关闭弹窗。
- 使用共享的创建方式选择弹窗，遮罩使用 `@click.self` 关闭。

### 5.2 总结集汉堡菜单

保留“生成总结”和高频排序动作；导入、批量、重命名、删除进入现有 `ActionMenu.vue`。删除单独使用危险样式和二次确认。

### 5.3 书信类型

将正式信、便签、短信、邮件的分段按钮改为与番外类型相同的可搜索下拉框，并支持自定义类型名和类型提示词。

数据迁移要求：

- 旧 `formal`、`note`、`sms`、`email` 映射到四种内置类型。
- 新数据保存类型 ID、显示名和类型提示词，不只保存自由字符串。
- 根目录新建书信时隐藏“最近 N 封”，因为此时没有所属书信集，当前实现实际也不会附带旧信。
- 书信集内新建时显示“参考本书信集旧信”开关，默认关闭；开启后才显示数量。
- 回复默认包含被回复的书信，数量只控制额外旧信。
- 重写使用原信作为单独目标，不称为“最近 N 封”。

### 5.4 番外摘要解析

生成页增加：

- “同时解析番外摘要”开关。
- 仅允许选择 `operation = extract` 的正则规则。
- 摘要格式提示，明确 AI 输出必须与所选规则一致。
- 可选“从章节正文移除摘要块”；只有规则能明确定位完整摘要块时才允许启用。

处理顺序：

1. 保留原始生成输出。
2. 正常解析章节标题和正文。
3. 开关启用时，用所选规则从原始输出提取摘要。
4. 匹配成功：预览中单独显示摘要，保存时创建或更新该章节的自动摘要。
5. 匹配失败：显示“未匹配到番外摘要”，正文保持原解析结果，允许正常保存章节，不创建空摘要。
6. 用户之后仍可使用现有总结功能生成摘要。

重写同一章节时更新该章节对应的自动摘要，不产生重复摘要；手动总结不受影响。生成草稿和重放记录必须保存摘要开关、正则 ID 和格式提示。

结构化的可选 `summary` 输出字段仍是优先解析方式；用户选择的正则作为兼容现有预设的回退方式。

## 十二、明确不采用的方案

1. 版本切换后跳到顶部、底部、版本栏或按新旧内容百分比换算位置。
2. 因为选中文字重复就拒绝橡皮擦操作。
3. 修改一句话就为番外、书信或小剧场新增版本。
4. 摘要未匹配时让整次番外生成失败或保存空摘要。
5. 继续用 `defaultDock` 永久固定 Dock 归属。
6. 为每个阅读 App 单独实现悬浮菜单和橡皮擦弹窗。
7. 为每个内容 App 各写一套无版本、无预览的 JSON 导入逻辑。
8. 只更新教程文字而不补设置快照和续长查重的视觉/行为场景。
9. 点击设置快照列表行后下载并格式化完整 `settings.json`。
10. “全选”把保护项也加入待删除集合，或让同一文件同时拥有保护和候选身份。
11. 预设改名时只改酒馆文件名，不迁移预设绑定、阅读规则和条目库绑定。
12. 世界书改名时只复制 JSON 并删除旧文件，不迁移全局、角色、附加、聊天和插件联动引用。
13. 把世界书 `vectorized` 条目显示成绿灯。
