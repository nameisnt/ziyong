# 提示词与类型提示词复用

提示词系统已经改为注册式贡献。新增 App 不需要修改 `PromptsApp.vue` 或 `store/prompts.ts`，只要在自己的 App 模块里声明提示词定义。

## App 默认提示词

```ts
import { simpleXmlOutput } from '@/apps/outputDefinitions';

promptDefinitions: [{
  key: 'my-app',
  label: '我的应用',
  defaultPrompt: '这里填写这个 App 的默认生成提示词。',
  outputFormats: [
    simpleXmlOutput(
      'my-app.generate',
      '输出格式',
      '<result>\n  <title>标题</title>\n  <content>内容</content>\n</result>',
    ),
  ],
}]
```

效果：

- 提示词 App 自动出现“我的应用”卡片。
- 默认配置会自动补齐 `appPrompts['my-app']`。
- “输出与解析”会自动出现这项规则。

业务页面读取时可以使用：

```ts
const prompts = usePromptStore();
const appPrompt = prompts.appPrompts['my-app'];
const outputFormat = prompts.resolveOutputFormat('my-app.generate');
```

生成页面必须通过 `resolveOutputFormat()` 读取格式，不要在组件内再次维护一份 `buildOutputFormat()` 字符串。

## 输出与解析

每个输出格式必须有全局唯一 `id`、默认输出文本和默认解析字段。简单的 `title + content` XML 使用 `simpleXmlOutput()`；复杂结构使用 `xmlParser()`、`textField()`、`textListField()` 和 `objectListField()` 声明。

用户在提示词 App 中可以：

- 修改实际发送给 AI 的输出格式。
- 启用自定义 XML、JSON、标签文本或纯文本解析。
- 调整字段路径、列表路径、属性路径和正文保留方式。
- 粘贴样例测试解析，并恢复默认规则。

生成 adapter 使用 `parseConfiguredOutput()` 包裹原解析器。没有启用自定义解析时继续调用原解析器，旧输出和旧失败草稿保持兼容；启用后按当前规则解析，再由该 App 的 Zod 结果 schema 校验。

## 特殊提示词

特殊提示词适合“同一个 App 内的附加生成动作”，例如日记阅读反应、番外章节总结和论坛追加回复。

```ts
specialPromptDefinitions: [{
  key: 'my-app-special',
  label: '我的应用特殊提示词',
  defaultPrompt: '',
}]
```

读取：

```ts
const specialPrompt = prompts.specialPrompts['my-app-special'];
```

## 任务模板

任务模板用于管理动作级、会随本次配置变化的要求。动态内容通过占位符注入，避免把“由谁写给谁”“新开还是续写”等要求固化在 App 预设里。

```ts
taskTemplateDefinitions: [
  {
    actionId: 'generate',
    label: '生成我的应用内容',
    defaultTemplate: '请以{{actorName}}的口吻完成本次任务。',
    variables: [{ key: 'actorName', label: '执行角色名' }],
  },
];
```

adapter 的 `buildRequest()` 同时提供兼容回退和变量：

```ts
return {
  taskInstruction: `请以${config.actorName}的口吻完成本次任务。`,
  taskTemplateVariables: { actorName: config.actorName },
  appPrompt: config.appPrompt,
  outputFormat: config.outputFormat,
};
```

提示词 App 会按 `App + actionId` 显示、编辑和恢复任务模板。模板留空时，本次不发送任务层；旧配置加载后会自动补齐当前已注册模板。

## 类型提示词域

类型提示词域用于让 App 拥有自己的类型预设列表。

```ts
typePromptDomains: [{
  key: 'my-app',
  label: '我的应用',
  emptyLabel: '还没有我的应用类型提示词',
  defaultOpen: true,
  defaultPrompts: [{
    id: 'prompt_type_my_app_default',
    domain: 'my-app',
    name: '默认类型',
    prompt: '这里填写类型提示词。',
  }],
}]
```

效果：

- 提示词 App 的“类型提示词”区会自动出现这个分组。
- 默认类型提示词会在初始化、重载设置时补齐。
- `TypePromptConfig.domain` 已经是动态字符串，不再限制为 `extras` 或 `theater`。

业务页面筛选：

```ts
const { typePrompts } = storeToRefs(prompts);
const myTypePrompts = computed(() => typePrompts.value.filter(item => item.domain === 'my-app'));
```

## 导入导出

提示词导入导出包含：

- `appPrompts`
- `specialPrompts`
- `taskTemplates`
- `outputRules`
- `typePrompts`
- `quickPhraseGroups`
- `quickTemplateGroups`

App 新增提示词或任务模板 key 后，旧配置会在加载时补齐默认值。导入旧文件时也会在覆盖后补齐当前注册表里缺失的默认 key。

## 内置定义位置

内置提示词集中在 `src/apps/builtinPrompts.ts`：

- 总结、日记、番外、论坛、小剧场、书信默认提示词。
- 日记阅读反应、番外章节总结、论坛追加回复特殊提示词。
- 番外、小剧场类型提示词域。
- 输出格式和默认解析定义。
