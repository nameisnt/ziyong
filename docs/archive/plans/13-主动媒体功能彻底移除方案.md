# 13-主动媒体功能彻底移除方案

> 历史归档：`MEDIAREMOVE01A/B/C` 已全部完成并验证；本文件保留删除范围和验收证据。

## 一、当前唯一需求基线

用户确认彻底移除插件自带的主动媒体套件，不使用兼容层，也不保留其旧数据：

- 删除 `comfy`、`media`、`cloud-media`、`gallery`、`music`、`video` 六个 App；
- 删除 ComfyUI/云媒体生成、API provider、媒体资料库及工作台 Comfy 步骤；
- 删除对应提示词、输出规则、任务模板、预览草稿、生成任务、默认桌面分组、教程、备份域和内容迁移入口；
- 插件启动及相关配置导入时清除上述 App 的旧内容、配置和关联记录；旧完整备份中的媒体域不再兼容；
- 保留聊天、阅读器、小剧场和通用运行时对图片、音频、视频及附件的正常显示。

## 二、精确数据边界

直接删除三个顶层旧字段：

- `sillytavern_phone_media`
- `sillytavern_phone_comfy`
- `sillytavern_phone_cloud_media`

从共享数据中只删除以下关联：

- App ID：`comfy`、`media`、`cloud-media`、`gallery`、`music`、`video`；
- 提示词键：`comfy`、`cloud-media`；
- 任务模板：`comfy.generate-prompt`、`cloud-media.generate-prompt`；
- 输出规则：`comfy.generate`、`cloud-media.generate`；
- generation task / preview draft 中 App ID 属于上述集合的记录；
- 工作台 workflow 与 pending run 中 `appId=comfy` 的步骤；若一个非空工作流原本全部由 Comfy 步骤组成，则删除该工作流；
- 手机布局与明暗主题档案中上述 App 的排序、文件夹和图标/强调色引用。

不删除共享图标资源文件，不删除非媒体 App，不删除聊天消息、阅读内容、番外或小剧场正文中的媒体标签。

## 四、验收

1. 六个 App 不再注册、首页和教程中不可见，构建产物不包含其业务模块。
2. 启动清理对精确旧媒体字段和关联记录幂等，其他 App 数据逐字保持。
3. 旧媒体备份域不再注册；包含未知媒体域的旧备份按现有未知域规则拒绝，不静默丢弃。
4. 工作台不再提供 ComfyUI 步骤；混合工作流只移除 Comfy 步骤，纯 Comfy 工作流删除。
5. 聊天、阅读器与小剧场仍能显示图片、音频和视频。
6. 通过全量静态门禁、临时构建及 `350×700`、`390×844`、`430×900` 日夜代表场景。
