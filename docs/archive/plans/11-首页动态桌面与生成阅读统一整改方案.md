### 当前明确不做

- 不新增独立“生成中心 App”。
- 不把普通 toast、删除确认、导入确认或字段校验搬进动态页。
- 不在更新时自动覆盖已有用户桌面。
- 不建立固定且不可编辑的分类目录。
- 不在本轮顺手增加“全部应用搜索”“隐藏 App”“最近使用 App”或首页统计卡；这些旧设想不属于当前基线，用户以后明确提出时再独立登记。
- 不允许文件夹进入 Dock，也不在 Dock 满员时自动替换或挤出已有 App。
- 不把全部 Font Awesome 功能按钮一次性迁移到新图标库。
- 不把 App 内的 `vh` 机械替换为 `dvh/svh`。
- 不把媒体、关系图等非连续文本结果为了形式统一强塞进阅读器。
- 不从 reasoning 与旧 `rawOutput` 拼接伪造历史完整原文。
- 不把“插件文件仓库”快照功能误当作通用图片素材注册表。

## 二、当前代码事实与共同根因

### 2.1 首页并非从零开始

当前唯一布局模型已经是 `HomeScreenLayout v2`，保存：

- `appOrder`
- `dockOrder`
- `folders`

`PhoneHome.vue` 与 `core/appLayout.ts` 已经具备长按拖动、App 拖到 App/文件夹、文件夹改名、移出与解散。A01 也已验证既有长按指针链。因此本轮禁止另建第二套桌面/store；应修改这一唯一入口。

当前真实缺口：

1. 默认布局仍为 `folders: []`，所有 App 继续平铺。
2. 没有显式整理模式，用户难以发现拖动能力。
3. `GenerationTaskCenter` 直接占据桌面首屏。
4. `normalizeHomeLayout` 会自动解散单项文件夹，与当前语义冲突。
5. Dock 接收普通 token 与 folder token，满员后静默挤出最后一项。
6. 文件夹内部仍依赖前移/后移/移出按钮，不是统一拖动排序。
7. 第一页动态页尚不存在；当前分页全部来自 `appOrder` 切片。
8. 设置允许 `dockColumns` 为 3～5，现有布局还可能包含 Dock 文件夹；新上限不能在没有兼容迁移的情况下直接生效。
9. `homePageIndex` 是 `PhoneHome` 的局部状态，离开首页后重新挂载会回到默认页，不能满足“从动态任务返回动态页”。

本轮必须继续复用 `HomeScreenLayout v2`。默认推荐分组、单项文件夹保留和 Dock 拒绝规则本身不要求新 schema；文件夹自定义封面等新增元数据才允许进入单独的 schema 批次。

### 2.2 图标现状

当前依赖为 Font Awesome Free 7.3.1。App 注册保存 `fa-*` 名称，所有位置普遍以固定 `fa-solid` 渲染。Theme App 已有 `appIconOverrides`、三套映射型内置包和单 App 类名覆盖，但它们仍属于同一 Font Awesome 库；没有共享图标描述器、文件夹封面或安全图片资源类型。

现有自定义壁纸和字体并不使用“插件文件仓库资源 ID”，而是由设置 store 上传至 `user/files`，在 settings 中保存 `{id,name,path}`，删除时走快照与回滚事务。插件文件仓库 App 负责插件快照，不是通用素材注册中心。因此自定义 App 图标必须复用既有文件资源契约，或另建经过授权的共享 AssetStore；禁止直接发明并写入当前不存在的 `resourceId`。

### 2.3 完整原始输出尚未保留

当前主路径为：

```text
AI 返回
  → normalizeGenerationResponse
  → cleanGenerationOutput
  → cleaned.content 被命名为 rawOutput
  → adapter.parse(rawOutput)
```

被移除的 XML 前缀会与兼容 API reasoning 合并到 `generationRecord.reasoning`，但预览、任务、失败草稿和保存上下文得到的 `rawOutput` 已是清洗后正文。部分重解析消费者还会把解析器选中的 XML/标签候选重新写回 `preview.raw` 或 `failedDraft.rawOutput`，因此旧字段甚至不一定代表清洗后的完整响应。`RawOutputEditor` 重新解析前还会把编辑框直接替换为清洗结果。现有单元测试只验证清洗函数和 reasoning 合并，没有验证完整原文不变。

旧任务、预览草稿和失败草稿没有字段能够区分“清洗全文”“解析候选”和“完整模型正文”，历史全文无法可靠重建。新语义必须携带版本/来源标记；旧记录只能按 `legacy-unknown` 显示，不能将 reasoning 与旧正文拼接后冒充原始响应。

### 2.4 预览和详情只部分统一

日记、总结、书信、小剧场、番外和资料表已使用 `GenerationPreviewPage`；论坛使用自己的页面壳并在内部调用 `GenerationPreviewPanel`。写卡工坊、剧情梳理、剧情规划、关系网、媒体、云媒体和 App 工坊仍直接拼装 Panel 或 RawOutputEditor。共享预览目前没有统一 reasoning 入口，写卡工坊因此另建了 `ReasoningModal`。

主要文本详情已经大量使用 `ReaderDetailShell`，但仍有独立详情只复用 `DetailFooter`。媒体、关系图等没有传统正文阅读语义的对象允许明确标为“不适用”，不能为了形式统一强塞进阅读器。

### 2.5 动态页数据目前没有统一入口

`generationTasks`、`previewDrafts` 与失败草稿是三套不同生命周期：

- `generationTasks` 可以提供运行、暂停、中断、失败、完成和保存状态，但终态记录全局最多保留约 40 条。
- `previewDrafts` 可以提供 App、页面、路由参数和标题，但没有 `taskId/actionId` 关联。
- 解析失败草稿由各 App 分别使用 `createFailedDraftCollection` 保存，App registry 没有统一恢复项目 provider。

因此动态页不能只遍历任务，也不能在 UI 中猜测各 App 的失败草稿。需要新增共享只读登记契约，由 App 返回稳定的恢复项 ID、scope、标题、状态、数量和跳转目标；任务、预览与失败项的去重规则由共享聚合层负责。

### 2.6 视口单位现状

`src` 当前有 10 处高度视口单位：`PhoneOverlay` 顶层手机壳 1 处，其余 9 处位于全局编辑/阅读正文、菜单、相册、小剧场目录、提示词捕获、总结导入、视频和阅读工具弹层。另有 4 处 `vw` 宽度限制。

本插件的 App 运行在手机浮窗容器内，`vh/dvh/svh` 指向酒馆页面视口而非手机可用内容区。故内部正确方案不是机械替换为 `dvh`，而是确定手机壳高度后，由子页面使用 `height: 100%`、`min-height: 0`、flex/grid 和唯一滚动区分配剩余空间。

## 三、目标信息架构

### 3.1 首页页面模型

```text
PhoneHome
├─ 固定动态页（结构页，不进入持久 layout）
├─ 用户桌面第 1 页（默认进入）
├─ 用户桌面第 2…N 页
└─ 固定 Dock（最多四个 App）
```

固定动态页不能删除、重排或进入文件夹；持久化 `appOrder` 的索引不因它插入首页第一页而迁移。每次进入首页默认选择第一个用户桌面页，用户通过内容区向右滑动查看动态页。

默认页与返回页使用两种状态：

- 正常打开或重新进入手机时，固定进入用户桌面第一页。
- 只有从动态页打开某个恢复目标，并通过正常返回链回到首页时，才以瞬时导航状态恢复动态页。

该恢复目标属于 phone/navigation 生命周期，不写入 settings，也不修改 `HomeScreenLayout` schema；刷新、关闭手机或从其他入口回首页后不得长期黏在动态页。

### 3.2 动态页状态

动态页只消费权威状态与新增的统一登记入口：

- `generationTasks`
- `previewDrafts`
- `generationRecoveryProvider`（暂定名，由各 App 登记失败草稿与恢复路由）

显示规则：

1. **进行中**：`queued/running/pause-requested` 逐任务显示进度与停止入口。
2. **待处理任务**：`paused/interrupted/failed`，以及仍保留可恢复原文的 `cancelled`；不得因状态终止就当成可清理历史。
3. **未保存预览**：以 `previewDrafts` 为权威来源；同一结果已经形成预览草稿时，不再把对应完成任务重复计数为待处理。
4. **解析失败**：由 recovery provider 返回，按稳定恢复项 ID 去重，并按 `{scopeKey, appId, actionId/结果类型}` 聚合。
5. **已保存**：只显示数量与“清理记录”，不平铺每条历史。
6. **批量任务**：只有所有子项均为 saved 且 `draftCount === 0` 时才属于纯已保存；任何混合结果都进入待处理。
7. **工作台/非正文结果**：不得按名称猜测，必须在 provider/任务契约中明确分类，否则不进入一键清理。
8. 单个待处理项直接跳转；多个进入现有共享草稿管理或对应失败草稿目录。
9. 红点只统计进行中和真正需要处理的组，不把纯已保存历史计入提醒。

清理资格必须由共享 store 查询给出，UI 不自行推断。只有纯 `saved` 的终态任务可清理；带草稿、失败输出、暂停或混合结果的任务不可进入该批清理。

动态页内容区独立滚动，Dock 固定在首页底部。动态页不能依赖终态任务最多保留 40 条的缓存来证明“已经没有待处理草稿”。

### 3.3 推荐默认桌面

初始文件夹只用于新安装或用户主动“恢复默认桌面”。推荐语义为：创作、整理、阅读档案、设定提示、资料关系、媒体工具、工具、娱乐。下表是当前唯一归属，不凭名称临时猜测；写卡工坊属于创作，总结和剧情梳理属于整理。

当前推荐清单以稳定 App ID 为准：

| 位置 | App ID | 说明 |
| --- | --- | --- |
| Dock | `favorites`、`prompts`、`tutorial`、`settings` | 延续现有四个默认 Dock App；用户可在设置中改为 3 个并自行调整 |
| 创作 | `diary`、`extras`、`theater`、`forum`、`letters`、`card-writer`、`scene-planner` | 写作与下一步场景创作；不含总结/剧情梳理 |
| 整理 | `summary`、`storylines`、`bagu`、`content-converter` | 总结、剧情梳理、检测和内容整理 |
| 阅读档案 | `reader`、`archive`、`recovery`、`digest`、`chat-insert`、`stats` | 阅读、档案、备份、摘抄、楼层插入与统计 |
| 设定提示 | `preset-manager`、`preset-link`、`entry-library`、`worldbook-link`、`world-slots`、`mvu-modifier`、`regex-display`、`regex-wizard` | 酒馆预设、世界书、变量与正则相关工具；`prompts` 已固定在 Dock |
| 资料关系 | `profiles`、`relationship`、`timekeeper` | 人物资料、关系与时间 |
| 媒体工具 | `comfy`、`media`、`cloud-media`、`gallery`、`music`、`video` | 媒体配置、生成与阅读 |
| 工具 | `workbench`、`app-builder`、`theme`、`file-repository` | 工作流、自制 App、外观和插件文件管理；`settings` 已固定在 Dock |
| 娱乐 | `games` | 单项文件夹按当前语义保留 |

运行时创建的自制 App 和未来新增且未登记的 App 不由名称自动归类，追加到最后一个用户桌面页。若注册表中还有未列出的内置 App，`DISC-11` 必须把它作为清单缺陷报告并在实现前更新本表，不得在代码中静默归类。

已有用户布局不因升级整体重新分组。新增 App 仍按统一规则进入可发现位置，不能覆盖用户顺序。未在推荐清单登记的新 App 追加到最后一个用户桌面页，不自动创建“未分类”文件夹；需要新分类时由用户整理或后续产品批次明确决定。

新规则生效时只允许执行以下最小兼容迁移：

1. 旧 `dockColumns === 5` 调整为 4。
2. Dock 第五项及后续溢出 App 按原顺序追加回桌面，不覆盖任何项目。
3. Dock 内的文件夹 token 整体移回桌面，文件夹名称、成员和顺序保持不变。
4. 迁移结果必须可测试、可导出且不依赖当前屏幕尺寸；除此以外不重新编排用户桌面。

### 3.4 整理交互

- 首页提供“整理”文字入口，长按 App/文件夹也可进入。
- 整理期间顶栏显示“完成”，暂停普通首页翻页手势。
- 拖动项目跟随指针；其他项目实时平滑让位。
- App 在另一个 App 上稳定停留约 400ms 后显示成组预览，松手创建文件夹。
- App 拖到文件夹时高亮目标；拖出后回到明确桌面位置。
- 支持显式“新建文件夹”：名称 + App 多选，至少一项。
- 单项文件夹保留；空文件夹移除。
- 解散需明确操作，只移除容器并将内部 App 放回桌面。
- Dock 只收 App，容量达到当前 3/4 设置时拒绝并显示原因。
- Dock 容量取用户设置的 3 或 4，上限四个；旧值 5 按兼容规则迁移。
- 跨页拖动使用手机内容区内可见换页目标或页码停留，不依赖设备物理边缘。

### 3.5 当前聊天状态条与文件夹页面

- 现有大块当前聊天卡压缩为单行状态条，至少显示角色卡显示名、聊天记录名及“当前/历史只读”状态。
- 跳转酒馆当前聊天保留为明确主操作；刷新、重新定位等低频操作进入同一操作菜单，不在首页顶部堆叠多个无文字图标。
- 无当前聊天、读取失败和历史只读必须有不同文字状态，不能只用颜色表达。
- 文件夹在手机桌面内容区以内近全屏打开，保留顶栏、文件夹名、整理入口和关闭/返回，不继续使用狭小居中弹窗。
- 文件夹网格沿用首页当前行列密度与 App 名截断规则；不能为了文件夹固定为四列，也不能恢复物理边缘滑动返回。

### 3.6 动画契约

| 动作 | 动画语义 |
| --- | --- |
| 提起 | 约 120ms，轻微放大与阴影 |
| 排序让位 | 160–200ms transform 位移，不重排跳闪 |
| 成组/放入文件夹 | 目标轮廓与轻微缩放，完成后缩入封面 |
| 文件夹开合 | 约 180ms 的位置相关缩放和 opacity |
| 解散 | 容器淡出，内部 App 平滑排回桌面 |
| 页面切换 | 跟手位移，松手约 200ms 收束 |

禁止持续漂浮、呼吸、粒子、夸张弹跳和大面积实时模糊。`prefers-reduced-motion: reduce` 下取消非必要过渡，状态变化仍必须清楚。

## 四、共享图标目标

功能按钮继续使用 Font Awesome，避免一次性迁移全仓库。桌面 App 和文件夹通过唯一 `AppIcon` 组件渲染。图标身份是全局设置，颜色、背景与对比度由当前主题决定，禁止要求用户在明暗主题中重复选择同一个 App 图标。

目标描述器为：

```ts
type AppIconRef =
  | { type: 'fontawesome'; name: string; style: 'solid' }
  | { type: 'builtin'; name: string }
  | { type: 'image'; assetId: string };

type AppIconAsset = {
  id: string;
  name: string;
  path: string;
};
```

约束：

1. `HOMEICON01` 先建立渲染适配层：现有 App 注册图标和 `appIconOverrides: Record<string,string>` 继续按 Font Awesome 解释，不修改 schema。
2. `HOMEICON01` 可以使用仓库内受控、本地打包的内置资源；不得把未审查的原始 SVG/HTML直接写入 DOM，也不得在本批新增 npm 依赖。
3. `HOMEASSET01` 才允许增加全局 `AppIconRef` 映射和 `AppIconAsset[]`，并复用壁纸/字体的 `{id,name,path}` 上传、删除快照和回滚契约；不得借用插件快照仓库的资源含义。
4. 旧字符串覆盖由适配器解释为 `{type:'fontawesome'}`。旧记录不批量改写，并暂时保留其原有明暗主题差异；用户首次通过新选择器修改某 App 后，写入全局描述器并优先于两套旧主题字符串。
5. 文件夹默认显示内部前四个 App 的四宫格；文件夹自定义封面属于后续 schema 批，不夹进默认布局批。
6. 图标选择器提供搜索、分类、预览和恢复默认；“最近使用”只有存在明确持久化需求时才另行登记，不在本轮自动增加。
7. 用户图片不得以内联 data URL 或可执行 HTML/SVG 保存；删除仍被任何 App/文件夹引用的图片前必须阻止或要求用户明确替换。
8. 若采用新 npm 图标依赖、联网下载资源、新建共享 AssetStore 或变更 `user/files` API，必须停止并单独授权。

## 五、生成原文与解析正确模型

目标主路径：

```text
AI 响应
├─ originalOutput：完整模型正文，供预览、编辑、任务和失败恢复
├─ providerReasoning：兼容 API 独立 reasoning
└─ cleanGenerationOutput(originalOutput)
   ├─ parseInput：只交给 adapter.parse
   └─ removedContent：合并进入 reasoning
```

持久记录必须同时声明原文语义：

```ts
type RawOutputSemantics = 'legacy-unknown' | 'original-v1';
```

- 新生成记录、预览草稿和失败草稿保存完整正文时写入 `original-v1`。
- 没有语义字段的旧记录迁移为 `legacy-unknown`；它可能是清洗全文或解析候选，只允许如实展示，不能标称“完整原始输出”。
- 不通过拼接 reasoning、XML 前缀或解析结果猜测旧响应顺序。
- 该字段横跨持久任务、共享预览草稿和各 App 失败草稿，属于 schema/完整备份兼容迁移；`GENRAW01` 实施前必须取得明确授权。

不变量：

1. 清洗发生在解析前，但只作用于副本。
2. “原始输出”显示完整正文；点击重新解析不得先改写文本框。
3. 用户编辑后的完整文本是本次重解析输入；清洗仍只产生临时 `parseInput`。
4. 失败草稿保留完整文本和具体解析警告。
5. `providerReasoning` 与 XML 前缀 reasoning 都可在预览和保存后详情中折叠查看。
6. 没命中结束标签时 `parseInput === originalOutput`。
7. 保存业务只能消费解析结果；若确需保存生成原文，字段语义必须明确，禁止继续把清洗结果叫作 raw。
8. 所有重解析消费者不得执行 `preview.raw = parsed.raw` 或等价回写；解析器选中候选只能存在于解析诊断/结果字段。

## 六、统一预览与详情契约

### 6.1 生成预览

`GenerationPreviewPage` 是文本生成预览的页面骨架，`GenerationPreviewPanel` 是其内部唯一面板。共同能力：标题/来源、预览/原始输出/八股紧凑切换、reasoning 折叠、解析结果编辑、原文编辑重解析、警告、保存和草稿恢复。

论坛回复、小剧场混排 HTML、写卡多阶段、结构化资料等差异通过类型化 props/slots 表达。无法覆盖的消费者必须在契约中说明业务差异；禁止复制整个预览页。

失败恢复统一进入 `FailedDraftRepairPage` 或其共享会话，不能在 App 根页面再放一套 RawOutputEditor。

`DISC-11` 必须先将真实消费者固定为下表，未完成矩阵前不得开始抽象组件：

| 消费类型 | 首批对象 | 统一要求 | 允许差异 |
| --- | --- | --- | --- |
| 连续文本生成 | 日记、番外、小剧场、总结、论坛、书信 | 必须使用统一页面壳、原文、reasoning、重解析、八股、保存与失败恢复 | 论坛回复结构、小剧场文字+HTML、摘要等通过 slots/adapter |
| 多阶段文本生成 | 写卡工坊 | 使用统一页面壳和原文/reasoning/失败修复 | 保留阶段导航与分阶段解析区 |
| 结构化文本结果 | 剧情梳理、剧情规划、资料表、关系网、人物资料 | 逐项确认是否存在连续正文与保存版本；共用能成立的预览能力 | 结构化卡片、图关系与分区编辑可独立 |
| 媒体结果 | 相册、音乐、视频、云媒体 | 不强制套入文字阅读详情 | 仍必须复用全局按钮、错误、弹窗与导航契约 |
| 工具代码结果 | App 工坊等 | 共用原文、reasoning、失败修复入口 | 代码预览、运行与文件操作另行保留 |

统一页面只允许一个主要滚动所有者。页头、视图切换、正文、警告与底部操作的几何由共享壳决定；业务 slot 不得再指定独立视口高度。

### 6.2 阅读详情

`ReaderDetailShell` 是文本内容详情的唯一骨架，统一标题随正文滚动、reasoning、目录、版本、字体、夜间模式、悬浮菜单、置顶/置底和上一项/下一项。正文渲染与 App 特有操作使用插槽。

媒体播放器、关系图和纯表格若没有连续正文阅读语义，可标记“不适用”，但仍须使用全局按钮、菜单和导航契约。

阅读详情的首批强制消费者是日记、番外、小剧场、总结、论坛、书信、剧情梳理/摘要类连续文本。人物资料、关系图、媒体与工具代码先在矩阵中标记“适用/部分适用/不适用”，不得仅因为拥有 `DetailFooter` 就声称详情已经统一。

## 七、容器高度规则

1. 只有顶层 `PhoneOverlay` 可以根据浏览器可视区约束手机壳，并使用 `100vh` fallback + `100dvh` 或等价测量。
2. App、预览、详情、输入编辑器和文件夹内部禁止使用 `vh/dvh/svh/lvh` 决定主体高度。
3. 页面使用确定高度链、flex/grid、`min-height: 0` 和单一 `overflow: auto`。
4. 正文、网页混排和长输入只保留一个纵向滚动所有者。
5. 弹窗/菜单按手机容器可用高度限制，不按酒馆窗口 `vw/vh` 限制。
6. 增加静态守卫：除登记的顶层 allowlist 外，新 App 内视口单位视为失败。
7. 每个命中必须先归类为“顶层边界/正文滚动/弹窗菜单/短预览/媒体画布”，只修改同一根因；不把所有 `max-height: min(...vh...)` 当作相同问题批量替换。
8. 输入框、原文编辑器和弹窗必须额外验证手机软键盘/`visualViewport` 变化后，焦点内容、关闭按钮和提交按钮仍可到达。

## 十、验收矩阵

### 10.1 生成原文

- 同一 fixture 同时断言完整 `originalOutput` 和清洗后 `parseInput`。
- 外部普通/流式 reasoning 与 XML reasoning 均保存且不重复。
- 新预览、失败草稿、任务记录显示完整正文并标记 `original-v1`。
- 旧任务/草稿迁移为 `legacy-unknown`，界面不得称其为“完整原始输出”，也不得拼接伪造。
- 修改原文后点击重新解析，编辑框不被清洗动作改写。
- 无匹配、多结束标签、大小写、连续结束标签和解析失败均覆盖。
- 全库所有 `parsed.raw → preview/failedDraft rawOutput` 等价回写点均有迁移清单与回归证据。

### 10.2 预览与详情

- 日记、番外、小剧场、总结、论坛、书信至少各一条真实预览操作；写卡工坊覆盖多阶段。
- 特殊内容至少覆盖论坛回复、小剧场文字+多个 HTML、写卡多阶段。
- reasoning 展开/折叠、原文编辑重解析、八股切换、保存、失败恢复均改变真实状态。
- 详情覆盖目录、版本高度保持、字体、夜间、菜单、返回原位置。

### 10.3 首页

- 空任务、运行中、暂停/中断、单/多预览草稿、解析失败、取消但有原文、纯已保存和混合批量任务。
- 同一结果在 task、preview 和 recovery provider 同时可见时只统计一次；超过任务终态缓存上限后仍能发现草稿。
- 默认第二页、向右进入动态页、动态页跳转后返回第一页。
- 刷新、关闭手机或从非动态入口回首页后恢复默认用户桌面，不持久黏住动态页。
- 整理文字入口与长按入口。
- 排序、跨页、App→App 成组、App→文件夹、移出、单项保留、解散。
- Dock 设置 3/4、满员拒绝、文件夹拒绝、失败后布局不变；旧 5 项和 Dock 文件夹按规则无损移回桌面。
- 新安装默认布局、普通升级只做必要兼容迁移、主动恢复默认重建推荐布局。
- 当前聊天状态条覆盖当前、历史只读、无聊天和读取失败；文件夹近全屏打开且沿用桌面密度。
- 图标默认、旧 FA 覆盖、内置覆盖、失效图片、引用中删除阻止、恢复默认与日夜主题一致身份。

### 10.4 共同门槛

- `350x700`、`390x844`、`430x900`。
- 日间与夜间模式。
- 输入框/弹窗覆盖移动端软键盘与 `visualViewport` 变化。

## 十五、2026-08 首页文件夹、图标材质与控件密度修订基线

本节覆盖此前“文件夹在桌面只显示普通图标”的桌面展示语义；近全屏文件夹详情仍作为查看全部成员与整理的唯一完整入口。未被本节替代的布局数据、Dock、导入导出和图标资产语义继续有效。

### 15.1 当前确认需求

1. 创建或解散文件夹后，首页不得残留整理、拖拽、点击抑制、弹窗遮罩或滚动锁；普通 App、其他文件夹和桌面排序必须无需刷新酒馆即可继续使用。
2. 桌面文件夹改为 `2×2` 网格占位的大容器。前三个成员是可直接打开的快捷入口；第四格只展示其余成员预览与数量，点击第四格、标题或容器空白打开完整文件夹。
3. 大文件夹不能继续使用按 token 数量切片的分页。普通 App 占 `1×1`，大文件夹占 `2×2`，分页和拖动插入必须按实际网格容量计算；完整文件夹不能跨页截断。
4. “液态玻璃”本轮首先指首页 App 与文件夹的图标材质：强调色渐变、静态高光、半透明边缘和柔和阴影。用户图片图标保持原图，只增加不遮挡内容的边缘与阴影；不把所有业务卡片加上独立 `backdrop-filter`。
5. 控件语言遵循中文操作、标准行业缩写：`App/API/URL/ID/AI/NPC/JSON/JSONL/HTML/XML/Token/Regex/MVU/Dock` 可直接使用；`Gen/Del/Cfg/Imp/Exp/Prev/Rst` 等操作缩写禁止作为用户可见标签。
6. 返回、主页、关闭、刷新、搜索、新增、编辑、复制、收藏、展开、拖动和更多等低歧义动作可使用纯图标，但必须有 `title`、`aria-label`、禁用、加载和失败反馈。导入/导出、覆盖/恢复、删除/解除、解散、清空、插入、保存版本和重新解析保留短中文。
7. 控件密度分批处理：按钮批只调整按钮、标签页与图标按钮；字段批再处理短枚举与动态搜索下拉。不得通过全局隐藏文字或统一固定窄宽实现。

## 十六、首页操作入口与网页自然高度修订

### 16.1 当前唯一语义

1. 首页聊天状态行采用“菜单在左、聊天信息居中伸缩、仅历史聊天快捷动作在右”的结构。“操作”是低频菜单，只显示汉堡图标，但必须保留 `title` 与 `aria-label`；弹层从触发器左缘向右展开，避免在窄屏越界。
2. `ActionMenu` 的现有消费者继续默认显示文字并向右对齐；纯图标和左对齐必须由调用者显式声明。
3. 网页详情继续由外层阅读器连续滚动。iframe 高度只能测量插件注入的正文包装层，不能测量 `html/body` 或 iframe 视口；移除周期性上报。
4. 插件外壳在用户 `<style>` 之后强制取消 `html/body` 的固定/最小高度，并把统一内边距放到正文包装层。用户网页内部布局、颜色和交互不被改写。
5. 父层若连续收到“新内容高度 = 当前 iframe 高度 + 同一增量”的报告，应停止自动扩张并显示明确状态；真实内容后续变化、图片加载和 DOM 更新仍由正文包装层的观察器触发。
