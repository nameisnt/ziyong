## 二、拆分与不做事项

1. 每批只处理一个共同根因，按 `ROUTE01 → THEATER01 → REASON01 → SWIPE01 → PREVIEW01 → EDITOR01 → DRAFT01 → DRAFT02 → DRAFT03` 顺序执行。
2. `SWIPE01` 只读展示候选回复：默认显示酒馆当前 swipe；候选不能在插件内编辑、橡皮擦修改、保存为新版本或写回酒馆；不调用酒馆的 `swipe_id` 写接口，也不称为“版本”。
3. `THEATER01` 由阅读详情外层作为唯一纵向滚动所有者；HTML iframe 仍通过既有高度桥接自适应，不为普通文字新增局部滚动容器。
4. `REASON01` 同时统一原生返回、外部兼容 API 的普通/流式返回和 XML 前缀清洗；只有实际拿到的 reasoning 才保存，旧记录不伪造补全。
5. `EDITOR01` 仅处理“已保存内容的主要正文编辑”这一语义；短输入、120px 多行模板、160px 测试/预览、260px 长提示词均不在本批顺手调整。
6. 多草稿不自动淘汰、不设数量上限、不自动改名；首页只显示数量和“继续最新”，其余进入共享草稿管理弹窗。实际保存成功后只删除对应草稿。

## 三、持久化与授权边界

`DRAFT01` 会把 `preview-drafts` 备份域从 v1 演进到 v2，并迁移已有单草稿数据。这是 schema、备份格式和兼容迁移，属于第 07 号总则 11.4 的 C 级操作：在进入该批之前必须取得用户对以下一句的明确授权：

> 授权 DRAFT01 修改 `preview-drafts` 持久化 schema、备份域版本和 v1→v2 兼容迁移；不操作真实聊天、备份文件或外部 API。

在获得授权前，可完成不涉及 schema 的 `ROUTE01—EDITOR01`，但不得开始 DRAFT01—DRAFT03。
