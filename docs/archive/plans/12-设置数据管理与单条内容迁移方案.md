# 12-设置数据管理与单条内容迁移方案

> 历史归档：`DATAMGMT01`、`ITEMTRANSFER-DISC` 与 `ITEMTRANSFER01` A 组均已完成；资料单行语义随后由 `PROFILEBRIDGE02F` 修订并完成。B/C 组从未被本方案授权为当前待办。

## 一、当前需求基线

本方案覆盖以下当前有效要求，并以 `07-当前代码与UI复用审计及设计要求.md` 为执行约束：

1. 手机顶栏最多保留返回/主页、主题、关闭等页面级导航，不再放 App 内容迁移按钮。
2. App 整体内容、当前聊天备份与完整备份统一进入“设置 → 常规 → 数据管理”。
3. 单条内容导入从对应 App 的“新增”入口进入；单条导出放在详情页 `ActionMenu`，不占顶栏。
4. 单条导入默认创建新 ID；仅发生同 ID 冲突时，才允许用户明确确认覆盖。
5. 危险恢复、覆盖操作继续显示完整中文，不缩写，不用含义不明的图标代替。

以下旧语义失效：

- “每个 App 顶栏显示内容迁移按钮”失效。
- “设置常规首页直接平铺四个备份按钮”失效。
- “把整 App 备份域直接当作单条内容文件”失效。

## 三、界面结构

### 3.1 设置常规页

常规页仅显示一行“数据管理”，副说明为“App 内容、当前聊天与完整备份”。整行点击进入子页面，由手机原生返回键回到设置。

### 3.2 数据管理页

数据管理页分为两组：

- **App 内容**：使用可搜索下拉框选择 App，再打开现有内容迁移弹窗；只显示具有非草稿备份域的 App。
- **备份与恢复**：显示当前聊天身份、内容统计和体积，保留“导出全部、导出当前、导入当前、完整恢复”。

`ContentTransferOverlay` 的复制、合并、覆盖含义和事务回滚不改变。

### 3.3 单条内容

- 列表新增弹窗：`新建内容`、`导入单条内容`。
- 详情页 `ActionMenu`：`导出本条`。
- 文件必须声明 App、对象类型、对象版本和记录 ID；导入前由 App 自己解析并预览标题/类型。
- 默认生成新 ID；只有同 ID 冲突时显示“作为副本 / 覆盖原内容”，覆盖必须二次确认。

这部分需要新增共享能力契约，不能从整域 JSON 猜测“哪一层数组才是一条内容”。

### ITEMTRANSFER01：共享单条迁移能力

ITEMTRANSFER01 固定拆分如下：

1. `ITEMTRANSFER01A`：共享文件信封、注册能力、校验和事务回滚。
2. `ITEMTRANSFER01B`：九类 App 适配器，导入副本时重建条目及嵌套 ID，覆盖只允许同 ID 冲突。

单条文件 v1 必须包含 `format/version/appId/itemType/itemSchemaVersion/itemId/title/exportedAt/data`。共享层不得猜测业务数组；`data` 必须由对应 App 的 schema 校验。

## 五、ITEMTRANSFER-DISC 对象边界结果

现有 `contentReceiver` 只接收标题、正文、标签等转换源，适合“转换成新内容”，但会丢失版本、思维链、回复、父级关系和业务字段，不能承担无损单条导入导出。单条迁移必须由 App 提供专用适配器。

| 批组 | App / 单条根对象 | 必须随条目携带的依赖 | 建议 |
| --- | --- | --- | --- |
| A：已有明确详情对象 | 总结条目、日记条目、番外章节、论坛主题、小剧场、书信、摘抄、资料条目、场景方案 | 版本/思维链/回复等子对象；所属书籍、板块或资料表只携带最小描述 | 首批支持；导入时选择现有父级或新建父级 |
| B：对象可确定但依赖更强 | 媒体条目、世界书槽位、剧情线、关系图 | 媒体文件资源、世界书绑定、剧情节点/节拍、关系节点与边 | 第二批；先做资源与引用预检，禁止静默丢字段 |
| C：全局可编辑资源 | 条目库条目、正则显示规则、工作流、Comfy 工作流、云媒体配置、写卡文档、自制 App 定义及其内容 | 分组、动作步骤、连接引用、动态 schema、全局/聊天双域 | 独立适配；不能和普通文章条目共用一个猜测式解析器 |
| N/A：整体设置 | 主题、预设联动、世界书联动、聊天插入设置、小游戏状态、生成任务/预览草稿 | 本身不是用户在详情页阅读的一条作品 | 继续只在“数据管理”执行整域迁移，不添加详情导出 |

推荐 `ITEMTRANSFER01` 先只覆盖 A 组，并新增一个共享 `itemTransfer` 能力：由 App 明确提供 `list/export/parse/preview/import`，共享层只负责文件外壳、选择文件、冲突确认和事务边界。B、C 组另批实现，避免第一批为资源引用和动态 schema 引入静默兼容分支。

## 七、ITEMTRANSFER01 完成记录

首批 A 组已按当前父级列表语义完成，不自动创建、合并或猜测父级：总结、日记、番外、论坛和书信须先进入目标总结集/书架/番外集/板块/书信集；资料条目须先选择目标资料表；小剧场、摘抄和场景方案导入当前作用域的对应列表。该限制替代第五节中“导入时新建父级”的早期建议；新建父级属于额外产品语义，未在本批静默加入。

实现边界如下：

1. `PhoneAppModule.itemTransferProvider` 明确声明对象 schema、版本、导出、预览、导入、快照和回滚，不从完整备份域推测业务数组。
2. v1 文件信封固定包含 `format/version/appId/itemType/itemSchemaVersion/itemId/title/exportedAt/data`；App、对象类型、对象版本或业务 schema 不匹配时直接拒绝。
3. 默认“作为副本”会重建根对象及所有嵌套对象 ID，并同步重写对象内部对旧 ID 的引用；“覆盖原内容”只在当前目标存在同 ID 时出现并要求二次确认。
4. 总结、日记、番外、论坛、小剧场、书信、摘抄和资料详情复用 `ReaderDetailShell` 的阅读工具菜单导出；场景方案没有阅读详情，因此在历史方案单条“管理”菜单导出。
5. 列表入口复用 `ActionMenu` 与共享 `ItemTransferImportModal`；导入失败保留文件选择结果和错误提示，业务写入失败恢复 provider 快照。

验证证据：共享/九类 UI 契约 6/6；全量单元测试 339/339；全量静态门禁、备份/恢复/结构契约、样式守卫和严格 UI 复用通过；总结导入文件选择与同 ID 预览在 350×700、390×844、430×900 通过；论坛夹具真实执行复制导入并确认主题及回复 ID 全部重建；夜间 350px 弹窗由浏览器真实点击检查；正式 UI 交互/外观契约 75/75 与 15/15、临时生产构建通过。未改完整备份 schema，未操作真实酒馆数据、真实备份文件、外部 API、正式 `dist` 或 Git。

### 7.1 资料单行迁移修订（PROFILEBRIDGE02F）

资料 App 已切换为外部资料表，所以上述本地 `ProfileEntry`/本地资料表父级语义对资料 App 失效，其他八类对象和场景方案不变。资料单条文件现在使用 `external-profile-row`：导出必须位于显式映射的行详情；导入必须先在外部表页面选择当前聊天的显式映射；字段按业务 key 严格匹配，不按中文表头、列号或显示名称猜测。默认副本生成新的外部身份值，同身份冲突时才显示明确覆盖选项。旧 `profile-entry` 文件不会自动写回已停用的本地 store。

外部行无法由共享本地 settings 快照恢复，因此共享 provider 增加显式 `provider-owned` 事务模式；未声明该模式的现有 App 仍必须提供原 snapshot/restore。外部资料 provider 只通过公开 CRUD 和稳定身份执行写入及失败回滚。本修订以 mock 验证，未操作真实外部资料，也未修改完整备份格式。
