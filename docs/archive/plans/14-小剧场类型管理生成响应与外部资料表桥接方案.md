建立日期：2026-08-21

状态：产品实现已完成；真实外部资料写入验证仍属于另行授权的真实数据测试边界，不重新解释为代码待办。

依据：`docs/07-当前代码与UI复用审计及设计要求.md` 第九节“重复缺陷防复发交付协议”和第十一节“自动执行协议”。

## 一、目标与范围

本方案整理的是“主动媒体功能及旧数据、兼容层决定彻底删除”之后，直到本方案建立前已经确认的全部讨论内容。主动媒体删除本身仍由方案 13 管理，本方案不重复取得其删除授权，也不把更早的网页高度、首页玻璃样式等问题重新并入。

本轮范围包括：

1. 把当前“小游戏”二级入口拆成多个独立 App，并默认放入同一个桌面文件夹。
2. 修复从第三页或文件夹打开 App 后，返回却落到默认主页的问题。
3. 把预设绑定和阅读规则绑定集中到预设管理，并补全保存后角色编辑、双向迁移及内置预设隐藏。
4. 整理聊天档案当前聊天卡片，并增加全部聊天只读列表和不切换酒馆聊天的随机查看。
5. 收紧世界书槽位页面的空白、内边距和新增按钮位置。
6. 直接把楼层转换为番外或小剧场时，按紧邻上一层角色决定是否带入追加要求。
7. 审计同语义“操作/管理”弹出菜单，把菜单式入口统一到内容区左侧；不移动快速操作按钮。
8. 明确小剧场单条导入、单条导出和全部内容迁移的入口层级。
9. 补全小剧场自定义类型的分组选择、已有类型的分组显示，以及批量修改所属分组。
10. 在小剧场首页增加按当前可见范围随机选择类型的骰子入口。
11. 区分“本次类型提示词”和“类型库提示词”，禁止生成或重写前自动覆盖类型库。
12. 重写优先恢复目标版本当时实际使用、但可能没有保存到类型库的提示词。
13. 修复非流式生成把结构化响应对象隐式转换成多个 `[object Object]` 的共享问题。
14. 将手机“资料表”改造成 `可参考拓展/newshujuku-main` 的轻量客户端，不再维护第二套自行生成的资料数据库。

本方案不包含：主动媒体删除本身、首页整体视觉重做、全局按钮尺寸、阅读器布局、其他 App 的批量管理、真实聊天内容改写、完整备份格式改造、Git 提交或推送。

## 三、失效语义

以下旧结论不再用于实现：

1. 小剧场记录页保留只有一个“导入单条”的管理菜单。
2. 自定义类型生成时必定自动保存到类型库。
3. 修改已有类型后，只要点击生成就自动覆盖全局类型提示词。
4. 批量整理包含批量修改提示词正文或批量删除。
5. 骰子放在生成页类型下拉框旁，允许在已编辑本次提示词后无提示换型。
6. 手机资料表在外部资料库不可用时静默切回本地旧资料。
7. 复制 `newshujuku-main` 的实现代码或直接访问其 SQLite/文件目录。
8. 继续保留“小游戏 App → 选择游戏 → 游戏”的二级进入流程。
9. App 返回时不管来源都回到默认主页，丢失第三页或文件夹上下文。
10. 把预设绑定或阅读规则绑定继续留在生成设置中，与预设管理并存。
11. 预设迁移等同于删除，或只复制不处理来源而仍称“迁移”。
12. 隐藏内置预设后没有取消隐藏入口。
13. 聊天档案随机按钮切换酒馆当前聊天。
14. 楼层转换时向前搜索任意一条用户消息作为追加要求；只允许检查紧邻上一层。
15. 因为一个菜单适合放左侧，就机械移动所有右侧按钮。

## 四、现状与共同根因

### 4.1 单条迁移入口不对称

- 小剧场列表当前在记录页提供“导入单条小剧场”。
- 单条导出由详情页的通用 `ReaderDetailShell` 操作区提供。
- 全部内容迁移位于设置数据管理。
- 功能存在，但入口名称和位置没有表达“单条对象”和“整个 App 数据域”的差异。

根因：迁移粒度已有两个契约，页面却用泛化的“管理／导入／导出”描述，导致用户无法建立往返关系。

### 4.2 分组只完成了存储，没有完成管理闭环

- `TypePromptConfig` 已有 `groupId`。
- 首页能够按分组展示；生成下拉选项也携带分组名。
- 自定义入口只传类型名称，创建时没有传 `groupId`。
- 提示词 App 只能逐项修改 `groupId`，没有批量事务。

根因：分组被当成编辑器附属字段，没有作为类型库的一等整理能力。

### 4.3 本次提示词与类型库提示词混为同一可写状态

- 生成页文本域绑定 `generationDraft.typePrompt`。
- 运行生成前调用 `saveGenerationTypePrompt()`。
- 已有类型会被更新，自定义类型会被创建；生成失败前写入也已发生。
- 重写已有版本时，若存在生成回放，当前代码已经可以读取回放内的 `typePrompt`。

根因：一次生成的临时配置和长期类型库共用自动保存路径，写入时机错误。

### 4.4 非流式结构化响应被隐式字符串化

- 流式路径按增量字段处理。
- 非流式路径一次接收完整返回值。
- 当前规范化器主要识别字符串字段，不完整支持顶层数组或内容块数组。
- 数组落入 `String(rawResult)` 时，对象元素变成 `[object Object]`。

根因：共享响应边界仍假定“最终结果主要是字符串”，没有建立结构化内容块契约。

### 4.5 资料表存在两个潜在事实来源

- 手机资料表当前拥有独立 `ProfileTable`、`ProfileEntry` 和生成、导入导出、消费者调用。
- `newshujuku-main` 已通过 `window.AutoCardUpdaterAPI` 提供读取、更新回调、CRUD 和打开完整界面的能力。
- 直接让两套 store 并存会造成显示、写卡、时间确认和备份来源不一致。

根因：手机资料表最初被设计成数据所有者；新目标要求它降为外部数据源的客户端。

### 4.6 小游戏组件已经分开，App 与路由仍被总入口捆绑

- 各小游戏已有独立 Vue 组件和独立设置字段。
- `Game2048App.vue` 仍维护小游戏总列表，并通过 `games/play?game=...` 二次路由选择实际游戏。
- 桌面只认识一个 `games` App，因而用户必须先进入总入口。

根因：业务组件和存储已经具备独立性，但注册层仍把它们包装成一个 App。

### 4.7 桌面来源页没有成为返回栈的一部分

- 从第三页或文件夹打开 App 时，来源上下文可能只存在于桌面当前状态。
- App 内返回或关闭详情后，部分路径使用硬编码主页/默认页替代真实上一层。

根因：路由只记录目标 App 页面，没有稳定记录“从哪一页、哪个文件夹进入”。

### 4.8 预设能力分散且迁移语义未闭环

- 预设绑定、阅读规则绑定和生成时选择属于同一个预设对象，却可能出现在不同页面。
- 插件预设条目复制时可选角色，但保存后编辑能力不完整。
- 酒馆预设和插件预设之间已有读取/导入基础，但“迁移”还需要目标成功、来源移除、失败可见的事务语义。
- 内置预设隐藏还必须具备取消隐藏和当前选择处理。

根因：预设详情没有成为预设相关配置和生命周期操作的唯一入口。

### 4.9 聊天档案当前页只完成了备份动作，没有完成浏览入口

- 当前聊天卡片状态文字在窄屏可能被固定按钮布局挤压。
- 卡片下方空间没有承载同角色聊天档案列表。
- 随机聊天的目标是只读查看档案，而不是切换酒馆当前聊天。

根因：当前聊天备份与历史档案阅读被拆成不同入口，没有共用只读打开语义。

### 4.10 世界书槽位和楼层转换缺少明确上下文规则

- 世界书槽位的数量、新增动作和固定世界书说明没有形成紧凑工具行。
- 楼层转换已有 Extras/Theater 目标和生成页 `userRequirement`，但没有把紧邻用户楼层作为转换上下文传递。

根因：页面动作没有绑定到其直接上下文；一个表现为按钮悬空，一个表现为转换时丢失用户补充要求。

### 4.11 菜单式操作与快速操作使用了同一种右侧堆叠习惯

- “管理/操作”弹出菜单代表一组低频动作，适合跟随内容上下文并放在左侧。
- 快速操作、主按钮、字段尾部动作和顶栏导航有不同位置语义，不能一起移动。

根因：此前按按钮外观排位置，没有先区分“菜单触发器”和“立即执行动作”。

## 五、目标交互设计

### 5.1 小剧场首页

```text
[ 搜索类型或历史内容……………………………… ]

[ 小剧场记录（3） ]                         [ 导入 ]

[ 最近使用 | 全部类型 ]                     [ 骰子 ]

[ 自定义 ]
分组名称
[ 类型 ] [ 类型 ] [ 类型 ]
```

要求：

- “导入”和“骰子”均使用 `.pc-icon-btn`，具备 `title`、`aria-label`、禁用态和点击反馈。
- 导入按钮不放入顶栏，不增加第五个顶栏操作。
- 骰子的随机池来自当前实际显示的类型：当前范围、搜索词和隐藏状态共同决定。
- 随机命中后直接进入生成页；固定测试随机源以验证命中对象，不用概率截图代替。

### 5.2 自定义类型和生成页

已有类型：

```text
小剧场类型
[ 弹幕体                                      ▼ ]
所属分组
[ 表现形式 ]
本次类型提示词
[ 可编辑，但默认只影响本次生成                  ]
[ 保存到类型库 ]  （仅发生修改后可用）
```

自定义类型：

```text
类型名称
[ 输入名称                                      ]
所属分组
[ 未分组                                      ▼ ][＋]
类型提示词
[                                                ]
[ ] 保存为新类型
```

要求：

- 已有类型的所属分组在生成页只读显示；移动分组统一进入类型整理页面。
- “本次类型提示词”始终属于当前生成草稿。
- “保存到类型库”是独立显式动作，不与“生成”共用事件。
- 自定义类型未勾选保存时保持 `typeId` 为空；类型名称和提示词仍写入生成回放。
- 现场新建分组复用现有提示词分组 store，不建立 Theater 私有分组数组。

### 5.3 批量修改所属分组

在提示词 App 的“小剧场类型”区域增加“整理”模式：

1. 点击“整理”进入多选。
2. 类型卡出现选中状态；普通点击只切换选择，不打开详情。
3. 分组标题提供“选择本组”，可跨组累计选择。
4. 操作区仅提供“全选”“移动到分组”“移至未分组”“取消”。
5. “移动到分组”打开中间弹窗，可选择已有分组或新建分组。
6. 一次 store mutation 更新全部选中项，并只触发一次持久化。
7. 本批不增加批量删除和提示词正文批处理。

### 5.4 重写的提示词来源

权威顺序：

1. 目标版本的 `generationReplay.config.typePrompt`。
2. 旧条目没有回放，但 `typeId` 仍指向有效类型：显示提示后使用当前类型库提示词。
3. 没有回放且类型不存在：生成按钮禁用，要求重新选择类型或填写本次提示词。

不得把当前类型库内容写回旧版本快照；不得因类型库已删除而清空条目已有回放。

### 5.5 非流式响应规范化

共享规范化器应识别：

- 纯字符串。
- Chat Completions 风格的 `choices[0].message.content` 与 reasoning 字段。
- 顶层内容块数组。
- `content` 内的字符串数组和对象数组。
- 常见正文块 `text`、`content`。
- 常见思维链块 `reasoning`、`reasoning_content`、`reasoningContent`、`thinking`。

约束：

- 只拼接已识别的文本块。
- 不对对象执行隐式 `String(object)`。
- 加密签名、工具调用对象和未知元数据不能进入可见思维链。
- 完全不识别的返回值进入明确失败状态，并保存安全、可读的诊断快照供检查。
- 规范化后再执行思维链清洗和业务 XML 解析。
- 原始文本区保留规范化前后语义可解释的文本；思维链继续进入独立折叠区。

### 5.6 外部资料表桥接

权威运行时入口：`window.AutoCardUpdaterAPI`。

基础读取流程：

1. 打开资料表 App 时检查 API 是否存在。
2. 调用 `exportTableAsJson()` 获取当前合并表数据。
3. 排除元信息区；以 sheet 的 `uid/name` 作为表标识和显示名。
4. `content[0]` 作为表头，其余行作为数据。
5. 注册 `registerTableUpdateCallback()`；收到通知后重新读取。
6. App 卸载时调用 `unregisterTableUpdateCallback()`。
7. 聊天切换和重新进入 App 时主动刷新。

缺失状态：

- API 不存在时使用 `EmptyState.vue` 显示“未检测到 SP·数据库/newshujuku”。
- 提供“重新检测”；若外部 API 支持，再提供“打开完整数据库”。
- 不创建空的手机资料表，不回退旧 store，不显示伪成功。

外部写入必须使用公开 CRUD：`updateCell`、`updateRow`、`insertRow`、`deleteRow`。不得直接修改 `exportTableAsJson()` 返回对象。

### 5.7 小游戏独立 App 与默认文件夹

- 为 2048、猜数字、五子棋、扫雷、数织、黑白棋、贪吃蛇、数字华容道、纸牌、数独等当前已存在的游戏逐一注册稳定 App ID。
- 每个桌面图标直接挂载对应游戏组件，不再进入总列表后调用 `openMiniGame()`。
- 初始桌面把这些 App 放入一个“小游戏”文件夹；用户之后仍可拆出、移动或重新分组。
- 拆分只调整 App 注册和路由壳，各游戏继续使用现有 `miniGameFields`，不得复制 store 或改变持久字段。
- 原 `games` 总入口在确认没有路由消费者后移除；不能长期保留新旧两套入口。
- 已有用户桌面布局如何接收新增 App 必须先按当前动态桌面规则验证；若需要布局迁移或 schema 变更，停止并单独授权。

### 5.8 来源页返回

打开 App 时将桌面来源记录为导航上下文：

```text
来源桌面页 + 来源文件夹（可空） + 来源滚动/选中上下文
  → App 页面栈
  → 返回退出 App
  → 恢复原桌面页/原文件夹
```

- 左上返回仍只退当前 App 内上一层。
- 从 App 根页返回才恢复来源桌面上下文。
- Home 按钮仍明确回默认主页，不承担“返回来源”语义。
- 关闭手机只关闭覆盖层；重新打开时遵守现有状态恢复规则，不借本批改变产品语义。
- 禁止为第三页单独写特判；修复应落在共享 App 打开/返回入口。

### 5.9 预设管理统一入口

预设详情承载：

1. 查看和编辑预设条目。
2. 编辑条目名、角色、启用状态和正文。
3. 设置/解除预设绑定。
4. 设置/解除该预设的阅读标题和正文规则。
5. 在“管理”菜单执行改名、迁移、隐藏/取消隐藏和删除等适用动作。

迁移规则：

- 酒馆预设→插件预设：先创建并验证插件预设，再请求删除来源酒馆预设；任一步失败都显示实际状态，不报告整体成功。
- 插件预设→酒馆预设：先创建并验证酒馆预设，再删除来源插件预设。
- 重名时停止并让用户选择新名称，不自动覆盖。
- 迁移和删除在菜单中是两个独立动作，文案不得互相替代。
- 迁移会修改酒馆或插件实际预设，属于 C 级操作；mock 可自动测试，真实迁移必须逐次授权。

内置预设隐藏规则：

- 隐藏只影响生成模式选择器，不删除预设内容和引用。
- 预设管理提供“显示隐藏项”范围，隐藏项可进入详情并取消隐藏。
- 若当前生成设置正选中将被隐藏的预设，隐藏前给出明确影响并要求重新选择；不得静默改成另一预设。

### 5.10 聊天档案浏览与随机查看

当前聊天页从上到下改为：

```text
[ 当前聊天身份与备份状态卡 ]
[ 立即备份 ][ 阅读备份 ][ 导出 ][ 导入 ][ 插入空聊天 ]
[ 全部聊天                                      🎲 ]
[ 聊天 A ]
[ 聊天 B ]
[ 聊天 C ]
```

- 状态卡允许必要换行，不把重要备份状态截断到卡片外。
- 全部聊天列表独立滚动，使用角色显示名和聊天名区分。
- 点击聊天和骰子命中统一调用“打开档案只读详情”，不调用酒馆聊天切换 API。
- 从只读详情返回，恢复当前聊天页的列表滚动位置。
- 随机池只包含可读取的其他档案；是否包含当前聊天必须在实现前以现有列表语义固定，并写入批次契约，不能每次结果不同。

### 5.11 世界书槽位紧凑布局

```text
[ 0 个槽位                                      ＋ ]

固定世界书
当前聊天                              [ 立即同步 ]
当前聊天没有槽位……

[ 搜索槽位、关键词或内容                         ]
[ 空状态或槽位列表                               ]
```

- 数量和新增按钮共用 `.pc-compact-toolbar`。
- 搜索、空状态和内容列表使用共享字段、卡片和 `EmptyState.vue`。
- 只缩减无信息价值的空白和局部排列，不借此修改槽位数据语义、同步 API 或世界书蓝绿灯规则。

### 5.12 楼层直接转换的追加要求

转换入口必须传递明确的来源消息 ID。转换时只检查该 ID 紧邻上一楼：

- 上一楼角色为 user：正文原样写入目标草稿 `userRequirement`。
- 上一楼角色为 assistant/system、上一楼不存在或正文为空：追加要求为空。
- 不越过 AI 楼层继续向前找用户消息。
- swipe 只使用当前激活 swipe 的正文，不读取其他候选。
- 自动带入仅发生在“楼层直接转换为番外/小剧场”入口；普通新建和重写不读取聊天最后用户消息。
- 生成后由现有 generation replay 保存最终 `userRequirement`，失败草稿也必须保留。

### 5.13 菜单触发器位置规则

先全库列出具有以下特征的候选：点击后展开两个以上低频操作、触发器文字为“操作/管理”或汉堡菜单、位于内容上下文行而非全局顶栏。

适用时：

- 触发器放在内容上下文行左侧。
- 使用汉堡或省略图标，去掉重复的“操作/管理”文字。
- 保留 `title`、`aria-label`、打开态和外部点击关闭。

不适用：

- 顶栏返回/Home/主题/关闭。
- 需要一眼可见的主动作和快速动作。
- 下拉框自身箭头、字段尾部按钮。
- 危险动作的独立确认按钮。
- 只有一个动作的按钮。

每个候选必须在验收记录标记“移动”或“不适用及原因”，禁止按 CSS 选择器批量换位。

## 七、消费者影响审计

资料表切换不能只修改 `ProfilesApp.vue`。已确认需要逐项处理的消费者包括：

- `src/apps/timekeeper/`：姓名和出生日期列映射。
- `src/apps/card-writer/`：写卡成品写入目标表及字段映射。
- `src/apps/contentReceivers.ts`：内容转换的资料表接收器。
- `src/components/ProfileEntryPicker.vue`：改为外部表/行选择器。
- `src/item-transfer/providers.ts`：资料单行文件的导入导出契约。
- `src/apps/workbench/`、`src/apps/storylines/`、`src/apps/relationship/`、`src/apps/world-slots/`：仅在确认实际依赖同一资料对象后逐项适配；不同根因不得顺手修改。
- 设置数据管理、统计和完整备份：停止把外部数据库当成手机自有数据域重复序列化。

字段映射不得只按中文列名猜测后直接写入。可以提供候选建议，但必须由用户确认目标表和列；映射失效时禁用写入并显示原因。

其他跨功能消费者必须审计：

- 小游戏独立注册会影响 App 注册表、主题图标映射、桌面搜索、默认文件夹、Dock 限制、设置数据管理和教程入口；只调整同一入口根因。
- 来源页返回会影响所有从桌面和文件夹打开的 App，应修共享导航入口，不给第三页或单个 App 写局部返回补丁。
- 预设统一入口会影响预设选择器、聊天绑定、阅读规则绑定、插件预设条目编辑和酒馆运行时桥接；真实迁移前必须保存来源/目标差异。
- 聊天档案列表必须复用已有档案扫描与只读详情，禁止重新扫描出第二份聊天索引。
- 楼层转换必须定位所有“转番外”和“转小剧场”入口，并共用一个紧邻楼层解析函数；其他内容转换目标不顺手改变。
- 菜单位置审计先形成候选清单，只有同为“内容上下文低频动作菜单”的命中项进入修改批次。

## 十一、授权与强制停止边界

建立本方案不授权修改生产代码。

后续可在单批明确授权后自动执行的内容：

- 只使用 mock/fixture 的源代码、测试和视觉场景修改。
- 不改变 schema、备份格式和外部公开接口的 UI/行为修复。
- 非破坏性的 lint、测试、UI 复用检查和构建。

出现以下情况必须停止并单独询问：

1. 修改持久化 schema、单条文件格式、完整备份格式或兼容迁移。
2. 修改共享公共 API，而不仅是内部实现。
3. 对真实 `newshujuku-main` 数据执行新增、修改、删除、导入或恢复。
4. 删除、迁移或覆盖旧手机资料数据。
5. 创建、删除、覆盖或迁移真实酒馆预设/插件预设。
6. 修改持久桌面布局 schema，或迁移用户现有文件夹/图标布局。
7. 调用真实外部生成 API或切换用户当前预设、世界书、API 设置。
8. 操作真实聊天、真实小剧场、真实提示词或真实备份文件。
9. Git 提交、合并、推送、发布或修改 `dist`。
10. 复现结果与本方案假设不符，或目标文件已有改动无法区分归属。

## 十二、完成定义

本方案不能因“构建通过”或“看了一张截图”标为完成。只有同时满足以下条件才可完成：

1. R14-01～R14-34 逐项标记完成、未完成、未验证或不适用。
2. 全部已登记缺陷均有实现位置和验证证据。
3. 每个按钮实际点击，成功、禁用和失败状态均验证。
4. 单条与全部迁移文件不会串用。
5. 批量分组只修改选中项的 `groupId`，没有额外正文或删除能力。
6. 生成成功、失败和停止均不会自动污染类型库。
7. 重写能够恢复指定版本当时实际使用的临时提示词。
8. 非流式响应的所有夹具均不出现 `[object Object]`。
9. 外部资料表桥接不存在双写和静默回退；旧手机资料按 PROFILELEGACY01 事务删除，外部映射和外部失败草稿保持不变。
10. 每个小游戏从文件夹直达且保留原存档，返回恢复真实来源页。
11. 预设绑定/阅读规则只有一个入口，角色编辑、迁移和隐藏均按各自契约验收。
12. 聊天档案随机查看不改变酒馆当前聊天。
13. 楼层转换只采用紧邻 user，并由失败草稿/回放保留。
14. 菜单位置审计有逐项适用表，没有机械移动快速操作。
15. 相关页面完成三档尺寸、日夜主题、导航和状态验证。
16. 最终 diff 仅包含已授权批次范围，并已运行 UI 复用检查。
