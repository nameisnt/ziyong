# 插件文件仓库与自动版本恢复方案

> 历史归档：第一阶段已经实现，本文件保留原始设计与安全边界，不得把“后续增强”自动视为已授权待办。当前数据与恢复规范以 `docs/05-数据备份统计与迁移.md` 和 `docs/07-当前代码与UI复用审计及设计要求.md` 为准。

更新日期：2026-08-13

状态：**第一阶段已实现**

## 一、目标

插件重要数据不再只依赖手动导入导出。利用酒馆现有 `/api/files/upload`、`/api/files/delete` 与用户文件读取能力，在当前酒馆用户的 `user/files` 中保存自动版本文件，并继续保留下载导出作为异地灾难备份。

本方案不要求修改酒馆后端，也不允许插件选择或写入任意服务器目录。

## 二、第一阶段数据范围

每份仓库快照包含：

1. 所有已注册的手机备份域，包括日记、总结、番外、小剧场、论坛、资料表、关系、时间、世界书槽位等。
2. 手机界面、阅读器、提示词、八股检测与恢复设置。
3. 插件私有预设完整正文，不只保存 `user/files` 路径索引。
4. 各备份域的 Schema 版本，用于恢复前校验与后续迁移。

API Key、导入字体二进制和自定义壁纸二进制继续遵守现有完整备份的脱敏边界，不写入仓库快照。

## 三、写入策略

- 快照文件使用不可变文件名；创建新版本时不覆盖旧快照。
- 快照正文写入成功后才更新仓库清单。
- 仓库清单同时保存在 `extension_settings` 和固定的 `user/files/phone-file-repository-manifest.json`。
- 内容指纹未变化时，自动快照不会产生重复版本。
- 默认每两分钟检查一次，首次加载后延迟十五秒检查。
- 默认保留最近十份未保护快照；受保护快照不参与自动清理。
- 删除先更新清单，再精确删除目标文件。删除失败最多形成孤立文件，不会误删其他数据。

## 四、恢复策略

恢复前必须完整读取并校验仓库快照。恢复操作复用现有完整备份事务：

1. 读取并验证手机备份 Schema 与各数据域版本。
2. 先把私有预设写入新版本文件，再切换其索引。
3. 使用现有事务导入手机设置与数据域，并统一重新载入各 Store。
4. 手机数据恢复失败时，尝试把私有预设回滚到恢复前记录。

仓库 App 提供快照详情、保护/取消保护、导出、删除和确认恢复。导入到仓库的外部快照默认自动保护。

## 五、安全边界

`user/files` 与酒馆用户数据仍位于同一台服务器或 Docker 数据卷。它可以防止浏览器缓存清理、设置索引丢失和普通误操作，但不能替代以下灾难备份：

- 整个 `default-user` 目录丢失；
- Docker 数据卷被删除；
- 硬盘损坏；
- 酒馆实例整体迁移失败。

因此仓库中的“导出”仍用于定期保存到服务器之外。

## 六、后续增强

后续可在酒馆现有文件接口能够安全列出指定前缀时增加服务端扫描，自动找回索引外的孤立快照；没有列举能力时继续依靠双重清单和固定清单文件恢复，不扩展任意目录访问权限。
