# DECISIONS

本文件记录当前仍有效的关键架构决策及理由。历史方案位于 `docs/archive/`，不得作为施工依据。

## ADR-001 文档入口收敛为三份当前文件

决策：`CURRENT.md` 记录当前规则，`DECISIONS.md` 记录关键决策，`CODEMAP.md` 记录真实代码结构和数据流。旧文档统一归档到
`docs/archive/2026-08-24-superseded-context/`。

理由：原 `docs/`
同时包含长期规范、执行流水、发布方案和过期路径，存在互相覆盖风险。三份文件能让后续开发先读当前事实，再按需考古。

影响：默认上下文不再读取 archive；若需要追溯历史，只能把 archive 当证据来源，不能直接执行其中待办。

## ADR-002 App 能力以注册表为边界

决策：所有手机 App 通过 `PhoneAppModule` 声明能力，使用 `definePhoneApp`、`registerPhoneApp`、`registerPhoneApps` 注册。

理由：注册表把 UI 入口、备份、生成、提示词、引用、收藏、统计、内容转换、单条迁移、作用域切换等能力集中成可枚举契约，避免每个 App 自己被全局功能硬编码扫描。

影响：新增能力优先扩展 `PhoneAppModule`
或使用已有字段；不要在全局页面里为单个 App 写特殊分支，除非该能力确实属于全局壳。

## ADR-003 内置与目录 App 混合注册

决策：传统核心内容域继续由 `src/apps/builtin.ts` 显式组成 `BUILTIN_PHONE_APP_MODULES`；其余 `src/apps/*/index.ts` 由
`src/data/apps.ts` 通过 `import.meta.glob` 自动注册。

理由：核心内容域共享大量内置生成、提示词、引用、收藏和统计工厂，显式组合更清楚；新域或工具域独立目录注册，降低中心文件膨胀。

影响：新 App 默认创建 `src/apps/<domain>/index.ts`；只有需要复用内置工厂组合的核心域才进入 `builtin.ts`。

## ADR-004 业务 App 归入 `src/apps/<domain>/`

决策：业务根组件和专属页面归属到各自 `src/apps/<domain>/`；跨业务组件继续留在 `src/components/`。

理由：当前代码已经完成多数旧根 App 迁移，`src/components/`
应表达复用层，而不是混放业务域。这样也让测试、视觉场景和目录所有权更容易定位。

影响：不要恢复 `src/components/*App.vue` 作为业务根路径；共享组件移动前必须证明消费者边界。

## ADR-005 不按行数机械拆大文件

决策：PhoneHome、CardWriter、Prompts、Reader 等根协调器只有在发现清晰单一职责边界时才拆分。

理由：这些文件剩余职责多为可写协调链，强拆会形成大参数袋、重复 store 消费或第二套状态。已有拆分选择的是活动页、只读布局投影、状态条、Theme 静态目录等低耦合边界。

影响：重构前先做只读边界审计；“文件太长”不是独立充分理由。

## ADR-006 聊天作用域统一 envelope 存储

决策：按聊天隔离的数据使用 `useChatScopedDomain` 管理，并持久化为 `__chatScoped` envelope。

理由：SillyTavern 当前聊天、角色、群组和旧无聊天数据都有兼容问题，envelope 允许同一字段存多聊天作用域并记录旧 scope 迁移。

影响：聊天切换由 `scopeSwitchHandler` 刷新 store；导入当前聊天只替换目标 scope，不应覆盖全部作用域。

## ADR-007 生成生命周期集中在 `generationService`

决策：生成 App 通过 `GenerationAdapter` 提供配置校验、请求构建、解析和保存，执行生命周期由
`src/core/generationService.ts` 统一处理。

理由：统一处理当前聊天限制、来源楼层、提示词模板、引用、称呼替换、酒馆/外部 API、流式输出、限速重试、abort、输出清理、replay、失败草稿和保存失败保留。

影响：单个 App 不应绕开服务直接调用生成 API；新增生成动作只实现 adapter 和注册 action。

## ADR-008 生成仅允许当前聊天写入

决策：`generationService` 在生成前断言当前查看作用域必须等于酒馆当前聊天；历史聊天只能浏览。

理由：历史作用域来自插件已保存数据，不能安全写回当前酒馆聊天、世界书或消息楼层。

影响：Archive/Reader 历史视图不得发起 AI 生成或写回真实酒馆状态。

## ADR-009 备份和迁移必须事务化

决策：完整备份、当前聊天备份、内容域迁移和单条迁移都要先校验、准备 staged data，再通过事务写入并支持回滚。

理由：备份导入会同时影响 extension_settings、多 App
store、插件预设和资源文件；中途失败若不回滚会造成设置与内存 store 不一致。

影响：新增备份域必须提供 schema、schemaVersion、import/export 和必要 rehydrate；单条迁移若不是 provider-owned，就必须提供 snapshot/restore。

## ADR-010 备份不保存敏感连接密钥

决策：JSON 备份清理外部 API
key；自定义壁纸和字体文件不作为普通完整备份内容迁移；首页图标资源只按完整备份 v3 的受控资源流程处理。

理由：密钥和本地资源文件有隐私、体积和路径可移植性风险。

影响：恢复备份后，连接密钥、字体和壁纸文件可能需要用户重新配置。

## ADR-011 UI 基础控件由全局样式和共享组件承担

决策：按钮、输入、卡片、表单动作区、生成、预览、引用、空状态、详情导航等基础模式优先复用全局类和共享组件。

理由：项目已建立 `pc-*` 样式系统和多个共享业务组件；单 App 重复定义会造成主题、尺寸和交互不一致。

影响：UI 改动后运行 UI 复用检查；保留局部重复样式必须有明确原因。

## ADR-012 主题使用 CSS 变量和 Theme App 静态目录

决策：主题值通过 `PhoneOverlay.vue` 写入 CSS 变量；主题预设、主题包、字体/图标/颜色/圆角目录由
`src/apps/theme/themeCatalog.ts` 独占。

理由：运行主题需要全局壳统一注入变量；静态目录迁出 ThemeApp 可以降低根组件体积且不改变行为。

影响：新增主题颜色先接入 settings schema 和 CSS 变量；不要在业务 App 硬编码绕过主题系统的颜色。

## ADR-013 发布产物继续跟踪但需授权构建

决策：`dist/index.js`、`dist/index.css` 是正式发布产物并继续跟踪；正式 `pnpm build`、提交和推送分别属于授权边界。

理由：SillyTavern 扩展发布依赖 dist；但构建会改写受跟踪产物，提交/推送会改变远端状态。

影响：本地验证可用 `build:check` 到 `tmp/build-check`；正式产物更新必须按用户授权执行。

## ADR-014 本地参考资料不得进入发布树

决策：`可参考拓展/` 是本地资料目录，保留本地文件但不进入发布候选；已授权退出跟踪发布时必须显式传入
`-UntrackIgnoredPath 可参考拓展`。

理由：该目录包含其他项目源码、构建产物和 source map，不属于本插件发布边界。

影响：默认安全推送不得重新加入本地资料；参考资料退出跟踪仍是 Git 删除视角，需单独授权。

## ADR-015 详情页共享转换与顶部导航语义

决策：详情页繁简转换复用 `chinese-simple2traditional@2.3.2`
核心；打开另一条内容、相邻版本和目录项时不保存前一内容的滚动位置，目标页从顶部开始。详情页保留思维链编辑，移除“修改句子”。管理页进入自身子编辑页再返回不属于内容切换，可恢复目录状态。

理由：复用同一转换核心可保持酒馆助手脚本的转换语义，同时避免加载带副作用的完整外部脚本；目标内容变化后恢复旧滚动位置会落到无关段落。

## ADR-016 批量删除复用共享选择状态

决策：有重复资料行和逐行删除动作的管理目录复用
`BulkSelectionBar`、`BulkSelectionCheckbox`、`useBulkSelection`，批量删除只确认一次。字段编辑器和详情页删除不纳入目录批量模式。

理由：批量模式属于目录级交互；把它扩散到编辑器内部会制造第二套选择语义和误删范围。

## ADR-017 预设管理与聊天绑定分离

决策：`preset-manager`
负责酒馆预设、插件预设及按预设共享的标题提取、正文提取、正文清理；酒馆目录将当前启用预设置顶，并在 App 会话内按预设保留分组展开状态，使条目子页返回时可结合共享路由滚动恢复回到原位。`preset-link`
独立负责聊天 scope 与酒馆预设的绑定、解除、正则重载和立即应用。

理由：阅读规则属于预设，聊天绑定属于聊天 scope。拆成两个 App 后，预设详情不再混入当前聊天状态，绑定也不依赖先打开某个预设详情。

## ADR-018 完整备份 v4 携带聊天档案资源

决策：完整备份 v4 在 v3 基础上加入 IndexedDB 中有内容的聊天楼层备份，并收集这些角色关联的主/附加世界书和当前聊天世界书；角色卡文件本体不导出。完整恢复替换聊天楼层备份并恢复同名世界书。

理由：只有插件设置而没有聊天正文和关联世界书的文件不能完整迁移已保存档案；角色卡本体体积和格式复杂，当前需求允许省略。

## ADR-019 备份查重按三种关系分层

决策：备份扫描同时产生字节完全一致、严格消息前缀续长、逐楼同位置匹配率至少 90% 三类结果。每组保护最新备份，其他项由用户选择，删除前重新下载并复核所属关系。

理由：精确副本和续长关系不能覆盖少量楼层变化的近似副本；分层展示能保留判定依据，并避免把 90% 相似冒充完全一致。

## ADR-020 插件随机宏只在生成期间生效

决策：`macro-builder` 生成 URL 参数形式的
`{{phone:dice?...}}`、`{{phone:pick?...}}`、`{{phone:assign?...}}`。`generationService`
在单次手机生成或最终提示词预览期间注册并解析，结束后注销。

理由：随机数量、是否重复和跨身份排除需要结构化参数；临时注册满足“仅插件内使用”，不会污染酒馆其他扩展或普通聊天宏环境。

## ADR-021 世界书条目复制保留源配置

决策：`worldbook-link` 的条目复制先进入可编辑副本页；现代世界书接口复制除 `uid` 和运行时 `extra`
外的完整标准条目，旧格式世界书则克隆原始条目、分配新 UID 后只覆盖副本页允许编辑的名称、正文和位置字段。已联动世界书保存副本后同步更新当前聊天配置。

理由：用“新建默认条目再填正文”会丢失关键词、策略、概率、递归和效果配置；保留源对象才能让复制真正用于快速增加相似条目，同时不修改原条目。

## ADR-022 助手脚本与第三方扩展分为两个原生 App

决策：参考 JSON 只作为行为依据，不执行其中的编译 bundle。`script-manager`
通过酒馆助手脚本树接口管理全局、当前预设和当前角色脚本，支持清单导出与一次确认批量删除；`extension-transfer`
通过 SillyTavern 扩展接口导出第三方扩展清单，并在导入预览后批量安装。全局安装遇到权限错误时保持失败，不自动降级为本地；安装完成后由用户手动刷新酒馆。

理由：助手脚本树属于 TavernHelper 当前上下文，第三方扩展属于 SillyTavern 服务端代码安装，两者的数据范围、权限和风险不同。原生 App 可以复用手机 UI、确认和错误反馈体系，避免参考 bundle 的外部依赖、嵌套弹窗和硬编码主题。

## ADR-023 状态栏是当前聊天的实时投影

决策：状态栏拆成两个 App。`status-display` 保留原 ID，只读取当前聊天绑定方案并实时渲染；`status-display-settings`
负责当前聊天方案选择、新建、编辑、复制、删除、正则配置、MVU 模板预览和配置备份。两者共享
`useStatusDisplayStore`，不复制方案数据。正则方案从后向前读取最新命中的可见 AI 原文并使用 `FrontendFrame`
safe 模式渲染；MVU 方案先读取 `Mvu.getMvuData()` 完成 `{{mvu:路径}}`
的 HTML 转义替换，再为查看页和预览页单独启用同源 trusted iframe 宿主桥，转发 `TavernHelper` 方法、`Mvu`、`$`、`_` 和
`toastr`，使已有网页按酒馆助手脚本的调用方式读取变量与响应交互。其他 `FrontendFrame` 使用方不启用该桥。

理由：状态栏随当前聊天和变量变化，不是需要保存、统计、收藏或迁移的一条内容记录；展示入口需要打开即看，配置入口则包含完整管理流程，拆分 UI 职责可以避免展示页被工具栏和编辑操作占用。共享 store 保留单一配置来源。正则结果来自聊天内容，继续禁用脚本；MVU 模板由用户在插件内维护，需要保留标签页、折叠和按钮等页面交互。

影响：`status-display-settings` 单独声明状态方案备份域和动态正则目标；`status-display`
不声明配置能力。状态方案进入全局配置备份，渲染结果不持久化；历史聊天只读视图不读取当前酒馆消息或 MVU。消息接收、修改、生成结束、聊天切换和重新进入展示 App 时刷新，不采用定时轮询或生成 token 级半成品渲染。

## ADR-024 正则 App 只管理有序规则资料

决策：`regex-display`
用显式分组和全局列表顺序管理提取、替换规则，规则详情与测试预览在弹窗中编辑，不再提供集中式“使用设置”。既有 `usages`
数据继续作为底层绑定结构，由 Reader、Preset Manager、Status Display Settings 等实际消费界面直接修改。

理由：规则定义与业务绑定是两类职责。用户在使用功能时选择规则更容易理解，也避免正则 App 需要了解所有动态目标；保留
`usages` 可避免已有绑定和备份失效。

## ADR-025 工作台切换聊天后建立新作用域基线

决策：工作台收到 `CHAT_CHANGED`
后不立即读取消息，而是等待宿主完成加载，核对切换序号，刷新手机当前 scope，再为新 scope 建立或修正 checkpoint。首次打开已有聊天默认从当前 AI 楼层开始计数，历史内容只通过手动运行处理。

理由：事件触发瞬间可能仍暴露旧聊天消息；直接计算会造成旧 scope 计数或生成写入错误聊天。默认不回填历史内容可避免切换聊天时突然批量生成。

## ADR-026 世界书联动编辑写回激活策略

决策：世界书联动编辑器支持 `constant`、`selective`、`vectorized`
三种激活策略，并在现代 TavernHelper 接口与旧世界书原始格式两条路径中写回策略和关键词。条目目录复用共享批量选择状态，将选中条目非破坏性复制为小剧场类型。

理由：只展示策略但保存时仅写名称、正文和位置会形成虚假编辑；同时保留三种策略可避免向量化条目被降级。批量转换创建新类型而不删除源条目，和既有单条转换语义一致。

## ADR-027 外部资料表取消映射层

决策：资料 App 直接读取 `AutoCardUpdaterAPI` 暴露的真实表、列和行，引用以 `sheetKey + rowIndex`
定位，生成和导入以真实列名写入。删除资料映射页面、映射存储、映射备份、映射消费桥和依赖映射的时间确认同步；需要写入的功能在自身界面选择目标表及必要列。

理由：映射层没有改变外部资料本身，却让浏览、引用、导入和生成都依赖一份额外配置，未配置时甚至阻断已经可读取的数据。直接模型与宿主 API 一致，读取路径更短，写入意图也由实际执行操作明确表达。

影响：普通资料浏览、搜索、详情、复制和引用不再要求预配置；不同表可以拥有不同列结构。跨会话持久引用依赖外部表键和行号稳定，外部工具重排或删除行后由使用方重新选择。

## ADR-028 普通 App 页面外边距由屏幕壳层统一承担

决策：普通 App 使用 `PhoneOverlay.vue` 中 `.pc-screen`
的页面外边距，业务 App 根页面不再重复添加同值 padding。卡片、编辑区、代码块和状态栏全屏网页按自身内容语义保留内部间距。

理由：根页面与屏幕壳层同时添加 14px 会让有效内容宽度在窄屏上额外减少 28px，并导致新旧 App 密度不一致。单一外边距来源可以让教程、工具和业务目录保持相同内容起线。

## ADR-029 插件宏保留可读 Unicode 参数

决策：`buildPluginMacro()` 直接保留普通中文，只对
`%`、`&`、`=`、`+`、花括号和换行等会破坏宏边界或查询参数的字符转义。解析继续使用 `URLSearchParams`，不新增第二种宏协议。

理由：完整 URL 百分号编码虽然可执行，但会让用户复制和检查宏时看到不可读字节序列。按参数值最小转义同时保持可读性与原有解析正确性。
